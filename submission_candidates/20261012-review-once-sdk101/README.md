# NOVA 행동 전 검토 후보

공식 SDK 1.0.1 기본 에이전트의 **다음 행동 초안을 같은 Doctor가 한 번 검토**하는 개발 후보다. 로컬 합성 검사를 통과하고 샘플 1회를 제출했으며, 임상 품질 검증 전인 미채택 버전이다.

루닛 보관 제출 코드의 `submission/app.py:682–716`은 초안 뒤 `review()`를 호출한다. `submission/review.py:259–289`는 마지막 사용자 질문의 요구 누락과 사실·안전·날조를 점검하고 수정 답을 함께 받는다. 기본 `suspect` 설정은 의심되는 답만 검토한다. 이번 NOVA 후보는 효과를 확인하기 위해 시간·호출 예산이 허용되는 각 행동 초안을 검토한다. 루닛의 조건부 트리거를 그대로 복제한 것은 아니다.

## 바뀌는 동작

`초안 SAY/EXAM/DONE → 시작 정보·원문 진료 기록과 대조 → KEEP 또는 수정된 한 행동 → 형식 검사 → 실제 행동`

- 환자가 방금 한 질문이나 걱정에 대응했는지 확인한다.
- 이미 답한 질문을 불필요하게 반복하지 않는다. 미응답·모호함·모순이 남으면 그 부분만 구체적으로 다시 묻는다.
- 의사가 앞서 한 말과 아직 확인하지 않은 가정을 환자 사실로 취급하지 않는다.
- 검토는 실제 환자 행동이 아니다. 검토문이나 초안을 진료 기록에 새 관찰로 추가하지 않는다.
- 내용 검토의 모델 자기평가는 품질 판정으로 사용하지 않는다.

직접 검토 호출은 초안당 최대 한 번이다. 검토 오류·빈 답·잘림·유효하지 않은 수정은 기존 유효 초안을 유지한다. 원래 초안의 의미가 안전하다는 보장은 아니다. 루닛의 최소 40자 규칙은 NOVA의 30자 행동 제한과 맞지 않아 사용하지 않는다.

## 비교 조건과 비용

기본선의 SDK, STEP/RECORD 프롬프트, 원문 이력, 30턴, medium, 초안 2048/최종 기록 4096 설정을 유지한다. 모델·temperature를 새로 지정하지 않는다. 검색, 추가 최종 기록 리뷰, 다른 HealthBench 프롬프트는 함께 적용하지 않는다. 변경 요인은 **예산 보호를 포함한 행동 전 검토 정책**이며 추가 프롬프트·호출·시간·토큰의 효과를 분리해 단정하지 않는다.

오류 없이 30행동과 최종 기록을 마치면 Doctor 호출은 기본선 31회에서 후보 61회가 된다. 기존 형식/일시 오류 재시도 때문에 실제 호출 수는 더 늘 수 있다. 61회 상한이나 시간 내 종료를 보장하지 않는다. 공식 제공 개발 도구의 세션 한도는 Doctor 200회, 입력 50만·출력 10만 토큰이다.

후보의 계측은 초안·검토·기록별 실제 client 호출 시도, 오류, 보고된 사용량, 미확인 사용량과 검토 유지·수정·실패·생략을 구분한다. 사용량 미확인을 실제 0으로 채우지 않는다. 출력 예산 계산에 쓰는 보수적 차감과 제공자가 보고한 실제 토큰은 별도다. 입력 토큰은 토크나이저 없이 다음 요청의 정확한 양을 미리 보장할 수 없다.

리뷰를 시작하려면 기존 기록 여유 180초와 SDK I/O timeout을 합친 시간 여유가 필요하다. 검토 후 기록 여유에 도달하면 추가 환자 행동을 보내지 않는다. I/O timeout은 전체 wall-clock 마감이 아니며, 기존 기록 작성의 재시도까지 완료를 보장하지 않는다.

## 다음 검증

합성 검사는 전달 형식·단일 호출·폴백·예산 보호·원문 유지·행동 전송 경로를 확인한다. 모형 응답을 직접 지정하는 검사로 의학적 판단이나 질문 누락 탐지 능력을 입증할 수는 없다.

현재 기본선의 공개 샘플 참고점수는 42.179이며 효율은 20/20이었다. 세 증례 집계만으로 낮은 다른 점수의 원인이 검토 부재라고 확정할 수 없다. 실제 대화 기록과 최종 기록을 확보하고, 전체 증례의 정보수집·질문 응답·모순·반복·안전·실패를 독립 검토한 뒤 비용 증가와 함께 비교해야 한다. 공식 리더보드 점수나 독립 일반화 평가가 아니다.

같은 공개 샘플을 다시 쓰면 개발 비교로 명시한다. 서버 모델 revision을 확인하지 못하면 같은 digest를 확보했다고 주장하지 않는다. 제공 벤치마크를 사용하려면 사례 ID·분할·변형 그룹·정답 비노출을 먼저 고정한다. HealthBench의 기존 평가용 180개 피드백으로 튜닝하지 않는다.

공식 기준선의 기존 ZIP은 유지한다. 사용자 승인으로 2026-10-12 17:57 KST에 이 후보의 샘플 검증 1회를 제출했다. 서버 파일 SHA는 `a54c6349062f02b986c9cf6a55dbdf17b9ae4f8d9676b244643b7051d4eba92c`로 12,066바이트 로컬 ZIP과 일치한다. 첫 증례 1턴·15초 후 `EXECUTION_INFRASTRUCTURE`와 **서비스 장애 · 복구 대기**가 표시됐고 파일 상태는 실행 실패다. 점수와 임상 품질 결과는 없으며 서버 모델 호출 수는 미확인이다. 중복 제출이나 공식 평가 요청은 하지 않았다.
