## 측정 도구

대시보드 제출 한 번이 25~35분이라 그 속도로는 A/B 가 불가능했습니다.
공개된 조각들로 채점을 로컬에 복원했습니다.

```
CoEval 공개 저장소의 conquer_val prompt-id 목록  (301개)
  +  공개 HealthBench Main 데이터셋
  =  리더보드와 동일한 301문항 · 기준 3,410개

공식 점수식:  Σ(met × points) / Σ(max(0, points))  · 문항 평균 후 [0,1] clip
```

로컬 45.0 vs 리더보드 47.8 — 3점 이내로 캘리브레이션됐습니다.

가장 오래 쓸 것은 점수 자체가 아니라 아래 둘입니다.

- `measurement/control.py` — **노이즈 바닥 측정.** 동일 설정을 반복해 판정 가능한 최소 차이를 정한다
- `measurement/paired_cv.py` — **평균 대신 문항별 승·패.** 한 문항이 만든 착시를 두 번 걸러냈다

## NOVA gpt-oss-20b 비교

[교수님 공유용 200문항 유형 목록과 검토 요약](benchmarks/HEALTHBENCH_FOR_PROFESSOR.md)을 정리했습니다.
질문 유형·대화 이력 구성·실험 결과·검토 요청 사항과 공식 원문 배포 경로를 확인할 수 있습니다.

루닛 호출 설정을 로컬 gpt-oss-20b로 비교하는 [HealthBench 실험 코드와 검증 기록](benchmarks/README.md)을 추가했습니다.
복구한 Consensus 검증 자료 200문항의 입력 검증 후, 3문항 × 2설정의 답변 6개를 생성했습니다.
기본 호출은 2개 완료·1개 잘림, 루닛 설정은 세 문항 모두 재호출 후 완료했습니다.
이 예비 비교는 총 264.897초와 9번의 호출이 들었으며, 당시 별도 HealthBench 채점은 수행하지 않았습니다.
실제 문항과 답변은 로컬에 보관하고, 공식 NOVA 진료 평가와 구분합니다.


기본·루닛·개선 설정의 답변 생성을 [로컬 대화 비교 화면](local_tools/README.md)에서 볼 수 있습니다.
개선 설정은 미확인 환자 정보를 추측하지 않도록 하는 지시 실험이며, 추가 학습은 수행하지 않습니다.

초기 비교는 3문항 × 3설정의 답변 9개를 생성했으며, 시간 차이를 정확도 향상으로 해석하지 않습니다.
답변 화면에 Markdown 읽기 모드와 200문항 탐색을 추가했습니다. 역할을 복원한 200문항의
기본·개선 400회 생성을 시도했고, 343개 정상 완료·56개 잘림·1개 실패로 부분 완료입니다.
Codex가 원래 200문항의 400개 기록을 검토했습니다. 기준 판정 834개를 확정하고 40개를
보류했으며 실패 1건은 생성 실패 0점으로 구분합니다. 전체 확정 점수는 없고,
가능한 점수 범위와 시간·토큰 기록은 [validation.json](benchmarks/validation.json)에 있습니다.
개발용 20문항만 지침 수정에 사용합니다.
후속 개선에서는 **gpt-oss가 답변을 생성하고 Codex가 독립 검증·지침 수정·재검증을 담당합니다.**
개발 20문항의 실패를 보고 일반 지침을 고친 뒤 같은 생성 조건으로 다시 비교하는
[Codex 검증 과정](benchmarks/CODEX_VERIFIER.md)의 지침 후보를 두 차례 비교했습니다. 후보 2개에서
새 답변 40개를 생성하고 독립 검토했지만 정확도 개선을 확인하지 못해 모두 채택하지 않았습니다.
두 번째 후보의 요청 시간 합은 개발 20문항에서 58.953초였으며 속도로 채택을 결정하지 않았습니다.
자기 검토는 보조 실험이며
자동 실행 대기 큐는 생성 전에 종료했습니다. 평가 180문항은 지침 수정에 사용하지 않습니다.
공식 gpt-oss·Ollama 문서에서 확인한 설정과 보조 실험은
[후속 개선 실험](benchmarks/REFINEMENT_PLAN.md)에 기록했습니다.
[정확도와 시간 검토 계획](benchmarks/EVALUATION_PLAN.md)에 고정 조건과 Codex 검토 절차를 기록했습니다.

같은 지침·이력에서 추론 강도만 바꾼 [low·medium 개발 비교](benchmarks/REASONING_EFFORT_DEV20.md)는 새 답변 20개 중 정상 17개·빈 답변 실패 3개였습니다. 40개 기록의 독립 검토를 마쳤지만 보류 4개와 새 안전 오류가 남아 채택하지 않았습니다.

후속 독립 재확인에서도 보류 4개를 유지했습니다. 호출 없는 [대조군 준비 검증](benchmarks/BUDGET_CONTROL_PREFLIGHT.md) 뒤 별도 실행 경로로 [같은 medium의 출력 한도 비교](benchmarks/OUTPUT_BUDGET_DEV20.md)를 진행했습니다. 한도만 2,048→4,096으로 바꾼 신규 20호출은 정상 18개·빈 답변 실패 2개였습니다. 정상 답변 17개는 기존 원문과 같으며 요청 시간·총 토큰은 늘었습니다. 설정을 가린 40개 기록의 독립 검토는 기준 판정 70개·보류 6개로 종료했습니다. 회복된 답변도 기준 점수 0이며 새 중대한 의학적 오류가 있어 채택하지 않았습니다. 반복 작업은 요청에 따라 5분마다 진행 기록부터 확인합니다.

이어 문구를 그대로 두고 지침 전달 위치만 바꾸는 [개발 20문항 실험](benchmarks/INSTRUCTION_PLACEMENT_DEV20.md)을 완료했습니다. 같은 medium·2,048토큰에서 새 20호출은 정상 18·빈 답변 실패 1·잘림 1입니다. 독립 검토 40기록의 기준 판정은 76개 확정·2개 보류이며 가능한 범위는 대조군 57.50–59.17, 후보 59.17–60.83입니다. 요청 시간 8.32%·토큰 2.72% 감소에도 새 안전·환자 정보 오류로 미채택했습니다. 기존 대조군·이전 판정은 유지합니다.

새 개발 근거로 사용자 원문을 다시 인용하는 [출처 색인 입력 실험](benchmarks/SOURCE_LEDGER_DEV20.md)을 준비하고 별도 실행기로 20문항을 각 한 번 생성했습니다. 신규 답변 20개는 모두 비어 있지 않은 완료 답변이며 기존 대조군의 정상 18·빈 실패 1·잘림 1과 partial 상태는 그대로입니다. 새 독립 검토는 기준 판정 78개·보류 6개, 기존 실패의 2기준 생략으로 종료했습니다. 가능한 기준 범위는 대조군 49.17–57.50·후보 50.83–55.00이며 새 중대한 약물 정체성 오류와 품질 개선 미확인으로 미채택했습니다. 요청 시간 3.93%·총 토큰 4.38%는 늘었고 단일 실행 관측입니다. 같은 후보는 재호출하지 않으며 실제 NOVA 적용도 하지 않았습니다. 이전 호출 없는 준비 기록은 유지합니다.
