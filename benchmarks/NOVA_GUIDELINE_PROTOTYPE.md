# 제공 지침 기반 오프라인 검색 프로토타입

2026-10-12 제공 파일 6개를 수령·검증하고, 지침 검색과 Doctor 입력 초안을 만드는 기능을 구현했습니다. 원문·색인·근거 패킷은 비공개 로컬에 유지하며, 공개에는 코드·합성 검사·집계만 저장합니다. 기존 root `run.py`는 보존하고 별도 SDK1.0.1 후보에 검색을 연결했습니다. 새 임상 성능 점수는 아직 없습니다.

## 서버 저장공간 실패와 E03 메모리 색인 수정

E02는 18:40KST 실제 샘플 제출에서 `/output`에 SQLite 색인을 만드는 중 `database or disk is full`로 종료됐습니다. 세 증례 모두 0턴·8/7/7초이며 점수는 없습니다. 앞선 로컬 tmpfs6GiB 시험은 실제 서버의 출력 저장공간 제한을 재현하지 못했습니다. 원래 E02 ZIP과 실패 기록을 보존했습니다.

E03 `submission_candidates/20261012-review-memory-guidelines-sdk101`은 색인 저장 방식을 RAM 전용 SQLite contentless FTS5로 바꿉니다. 원문 본문은 복제해 저장하지 않고 검색어 색인과 문서 메타데이터·byte offset을 유지하며, 검색 시 탑재된 원문을 다시 읽어 해시와 구간을 검증합니다. 임시 정렬도 메모리에 두고 종료 시 연결을 닫습니다. 같은 전체 말뭉치·질의·BM25·참고 예산·초안/검토·최종 기록·모델 설정을 유지합니다. 코드가 자체로 전체 RAM/CPU/하드 마감을 강제하는 것은 아닙니다.

실제 후보의 `prepare()`를 로컬 Linux Python3.12.15/SQLite3.46.1에서 CPU2·RAM8GiB·swap0·네트워크 차단·읽기 전용 루트/원문으로 실행했습니다. `/output`과 `/tmp`는 각각16MiB만 허용했습니다. 15,904문서·389,730구간 준비38.298초, 조회 포함38.723초, 컨테이너 명령39.391초, cgroup최대1,222,184,960바이트(약1.14GiB), 프로세스RSS576,446,464바이트, OOM0회, 생성한 색인/임시 파일0개입니다. SQLite페이지442,560,512바이트는 전체 프로세스 메모리와 다릅니다. arm64 Mac의 amd64 로컬 컨테이너 단일 관측이며 실제 대회 서버 통과를 뜻하지 않습니다.

15개 일반 검색어에서 기존 E02가 반환한 참고 메시지20구간이 정확히 일치했고 말뭉치/목록 해시도 유지됩니다. 이것은 검색 정합성 검사이며 임상 관련도나 답변 품질 검증이 아닙니다. 새24합성검사·private전체530검사와10파일 ZIP 격리 실행을 통과했습니다. ZIP36,090바이트, SHA `fcad1c128bb9a3b790220f0c556a1782a0aa039003ae151ba6a2725a7ff46ac4`이며 원문·DB·키는 없습니다. 실제 서버 처리와 점수는 [샘플 실험 기록](NOVA_DAY0_SUBMISSION.md)에서 추적합니다.

## SDK1.0.1 행동 후보에 연결한 단계

`submission_candidates/20261012-review-guidelines-sdk101`은 기존 1회 검토 후보에 오프라인 참고 검색을 연결합니다. `prepare()`에서 새 색인을 준비한 뒤 SDK의 ready를 보내고, 진료 중 시작 진술과 최신 환자 응답 두 개로 검색합니다. 긴 시작 진술이 최신 응답을 밀어내지 않게 어휘를 배분합니다. 의사의 추측이나 실제로 받지 않은 검사 결과를 검색 사실로 사용하지 않습니다. 환자의 인용문·부정문을 임상적으로 판별하는 검색기는 아닙니다.

상위 원문 최대2개를 같은 턴의 초안과 1회 검토에 함께 제공합니다. 원문·출처·라이선스·바이트 위치·해시를 유지하고, 마지막 기록에는 원문 참고 메시지를 첨부하지 않습니다. 별도 참고 정책은 일반 참고를 환자의 관찰로 승격하지 말라고 지시하지만 모델이 이를 지킬지는 실제 대화로 검증해야 합니다.

두 참고 메시지 전체를 직렬화한 UTF-8 크기는8,192바이트, 전체 messages 배열은65,536바이트로 제한합니다(SDK1.0.1의 JSON 구분자 기준, 바깥 HTTP body 제외). 한글 원문2개가 넘으면 낮은 순위 원문을 통째로 빼고1개를 보존합니다. 이것은 토큰 수가 아니며 실제 다음 입력 토큰을 정확히 예약하지 않습니다. 원래 환자 이력을 임의로 자르지 않고, 이력 자체가 한도를 넘으면 모델 요청을 막아 기존 기록 fallback으로 넘어갑니다. 검색 후 남은 시간을 재확인하지만 파일 읽기까지의 하드 마감 보장은 아닙니다.

기존 medium·2048/4096·30턴·STEP/REVIEW/RECORD 지침·지정 Doctor·SDK를 유지했습니다. 정상적인 한 행동의 Doctor 호출 수는 여전히 초안1+검토1이며 검색용 모델 호출은 없습니다. 검색 실패·검증 실패·정상0건·참고 크기 제외를 구분해 집계합니다. 원문·질의·환자 문자열은 공개 로그에 넣지 않습니다.

새 합성24검사, 관련101검사, private 전체506검사와 별도 ZIP의 격리 import→prepare→consult 검사가 통과했습니다. ZIP의 가짜 Doctor3호출은 실제 모델 요청이 아닙니다. 기존 실제15,904문서/389,730구간 색인에 일반 검색어15개를 입력해 원문20구간의 바이트·출처 해시를 재확인했습니다. 한글10질의에는 각1개, 영어5질의에는 각2개가 들어갔으며 선택된 참고 메시지 최대5,796바이트였습니다. 조회 합2.834초·최대1.103초는 이 Mac의 단일 관측이며 관련성·재현율·임상 품질을 뜻하지 않습니다.

새 ZIP은8개 런타임 파일,29,694바이트입니다. DB·지침·벤치마크·키는 포함하지 않습니다. 실제 모델 호출·서버 샘플 점수는 [샘플 실험 기록](NOVA_DAY0_SUBMISSION.md)에서 별도로 추적합니다. 기존 제출 ZIP은 변경하지 않았습니다.


## 현재 작동하는 흐름

`NOVA_GUIDELINES_DIR`의 제공 Markdown → 원문 바이트·목록·출처·라이선스 확인 → SQLite FTS5/BM25 색인 → 원문 구간·문서 ID·출처·바이트 위치 반환 → 환자 대화와 구분한 Doctor 입력 초안.

최종 실제 색인은 15,904문서, 389,730구간입니다. 이 Mac에서 19.48초, 최대 메모리 약165MiB, DB 1,266,274,304바이트(약1.18GiB)로 만들었습니다. SQLite 3.53.1/FTS5 환경의 한 번 관측이며 서버 성능을 보증하지 않습니다. 일반 질의 4개에서 5·5·5·0개의 결과를 받았고, 15개 원문 구간의 바이트 위치·전체/구간 해시·출처·라이선스를 독립 확인했습니다. 이는 조회 정합성 검사이며 임상 관련도·검색 재현율 검사가 아닙니다.

`nova/guideline_context.py`는 원래 system/user/assistant 메시지의 내용·역할·순서를 보존하며 공통 출처 지침과 별도의 참고 JSON을 삽입합니다. 대조군에는 같은 위치의 빈 참고 목록을 넣고, 후보에는 검증된 원문 구간을 넣습니다. 일반 합성 이력을 사용한 실제 3구간 입력 준비를 확인했습니다. 모델 호출·네트워크 호출은 0회입니다. 원문이 지시문처럼 보여도 참고 데이터로만 전달하며, 이 구분이 모델의 지시문 혼동을 완전히 막는다고 주장하지 않습니다. 참고 문자 예산과 실제 모델의 전체 입력 토큰 예산은 별도로 검증해야 합니다.

## 준비 함수와 로컬 Linux 제한 환경 확인

`nova/guideline_prepare.py`는 SQLite FTS5·JSON·MATERIALIZED 지원을 먼저 확인하고, 지정한 기존 출력 루트 안에 고유0700 작업 폴더를 만든 뒤 새 색인을 생성·검증합니다. `/tmp`처럼1777인 루트도 사용할 수 있고, 결과 DB는0400입니다. 실패 시 빈 검색 결과로 감추지 않고 원래 예외와 비공개 실패 기록을 남깁니다. 기존 root `run.prepare()`는 보존하며, 아래 새 후보의 `prepare()`에서 호출합니다.

실제 원문15,904개로 **로컬 Linux 준비 시험을 통과**했습니다. 기존 이미지를 사용해 Python3.12.15·SQLite3.46.1·x86_64·UID65532, 네트워크 차단, 읽기 전용 루트/원문 마운트, CPU2개, 메모리8GiB·swap0, tmpfs6GiB, 명령 제한600초를 적용했습니다. 준비 함수34.813초, 컨테이너 명령 전체65.349초, 메모리 최대2,033,729,536바이트(약1.89GiB), 프로세스RSS최대123,772,928바이트, OOM0회였습니다. tmpfs·파일 캐시를 포함한 cgroup 메모리와 프로세스RSS를 구분했습니다.

생성 결과는15,904문서·389,730구간·DB1,266,126,848바이트입니다. 원문597,185,304바이트의 내용 명세와 목록 해시가 앞선 Mac 색인 원문과 일치합니다. SQLite 버전과 환경이 달라 DB 자체의 크기·바이트가 Mac DB와 같다고 요구하지 않습니다. 원본을 변경하지 않은 APFS 복제본을 비공개 상위 폴더 안에서 읽기 전용으로 바인드했고, DB는 컨테이너의 임시 파일 시스템에 새로 만들었습니다.

이것은 로컬 가상화 환경의 단일 관측입니다. 실제 대회 서버의 파일 시스템 용량·이미지·성능 검증이나 모델 답변 품질 개선은 아닙니다. 준비 함수 자체는 자원 제한을 강제하지 않으며, 이번 제한은 컨테이너가 적용했습니다. 준비용합성17검사·private전체457검사·공개지정16모듈334검사가 통과했습니다(공개전체suite아님). 처음 준비 시험에서 기존 이미지의 옛 패키지가 새 모듈을 가린 문제는 마운트 위치를 수정해 해결했고, 실패 기록과 최종 성공 기록을 모두 보존했습니다.

서버형 경로를 쓰는 명시적 호출 예시는 아래와 같습니다. 실제 제출에 넣기 전 전체 입력 토큰 예산과 원문 검색·여러 턴 동작·최종 기록을 추가로 검증해야 합니다.

```python
from nova.guideline_prepare import prepare_offline_guidelines

# NOVA_GUIDELINES_DIR는 실제 읽기 전용 원문을 가리켜야 합니다.
state = prepare_offline_guidelines(output_root="/tmp")
```

## 로컬 실행

Python 표준 라이브러리와 FTS5가 있는 SQLite를 사용합니다. 원문 경로는 실제 다운로드한 `guidelines` 폴더 또는 서버의 `/opt/nova/guidelines`입니다. 출력 폴더는 본인 소유·0700으로 미리 만들고 원문 폴더 밖에 두세요. 기존 파일을 덮어쓰지 않습니다.

```sh
export NOVA_GUIDELINES_DIR=/path/to/extracted/guidelines
mkdir -m 700 results/local-guidelines
python -m nova.guidelines build --db results/local-guidelines/guidelines.sqlite
python -m nova.guidelines status --db results/local-guidelines/guidelines.sqlite
python -m nova.guidelines search --db results/local-guidelines/guidelines.sqlite --query hypertension --limit 3
python -m nova.guidelines search --db results/local-guidelines/guidelines.sqlite --query 인플루엔자 --language ko --limit 3
```

입력 초안은 본인이 준비한 원래 텍스트 메시지 JSON으로 만듭니다. 이 명령은 모델을 호출하지 않으며 출력에는 원문 구간이 포함되므로 비공개로 유지해야 합니다.

```sh
python -m nova.guideline_context --messages-file private_data/messages.json --query hypertension --db results/local-guidelines/guidelines.sqlite --output results/local-guidelines/request-draft.json
```

## 자료 품질과 남은 조건

자료 15,904개가 전부 최신 진료지침인 것은 아닙니다. 목록상 질환 개요9,656개·진료지침2,645개와 권고문·논문·요약·일반인 자료 등이 섞여 있습니다. 영어는90.53%이고 연도는1971–2026, 공란5개,2016년 이전899개입니다. 같은 출처URL의 중복은 문서 내용의 중복을 뜻하지 않습니다. 검색 결과의 문서 종류·대상·발행 시점·적용 조건을 확인해야 하고, 연도만으로 임상적 유효성을 판정하지 않습니다.

검색은 단어 기반입니다. 한국어 형태소·영한 번역·동의어·의미 검색·의학적 정확성·새 답변 품질은 미검증입니다. 구간을 자르는 과정에서 앞뒤 문맥이 충분한지도 별도로 확인해야 합니다. 검색 내용은 일반 의학 참고이며 환자의 증상·검사값·병력을 인증하지 않습니다. 벤치마크 질문·정답·평가 기준은 색인하지 않았습니다.

DB는 50MB 코드 ZIP에 넣을 수 없습니다. 대회에서는 읽기 전용으로 탑재된 원문을 사용하고, 준비10분·CPU2코어·RAM8GB라는 대회 조건에서 실제 서버의 동작을 별도로 검증해야 합니다. 위 로컬 Linux 제한 시험은 완료했지만 공식 서버 준비 통과로 해석하지 않습니다. 같은 UID의 악의적인 동시 경로 변경을 모든 시점에서 배제하지 못하는 한계도 유지합니다.

외부 API 호출은 제출 실행에서 금지됩니다. 제공 원문의 출처·라이선스를 보존하며 ND 등 변경본 배포 제한 자료의 색인/번역/요약본을 공개 저장소에 올리지 않습니다. [공식 개발 가이드](https://nova.snubhai.org/docs/), [참가 규칙](https://nova.snubhai.org/rules/)

제공 벤치마크의 전체 구조·중복·분할 품질은 [별도 분석](NOVA_BENCHMARK_QUALITY.md)에 있습니다. [전제·출처·미확인 구분 지침 초안](../prompts/doctor-evidence-first-v1.txt)은 함정 대응을 검토하기 위한 미시험 후보이며 이번 검색 구현이나 오늘의 제출 기준선에 자동 적용하지 않았습니다.
