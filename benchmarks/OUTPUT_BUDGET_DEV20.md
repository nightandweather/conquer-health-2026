# 같은 medium의 출력 한도 개발 비교

가설은 같은 지침·원문 이력·medium 추론·temperature 0·모델 digest에서 출력 한도만 2,048에서 4,096토큰으로 바꾸면 빈 최종 답변을 줄일 수 있는지 확인하는 것입니다. 개발용 20문항 전체를 사용하며, 기존 medium/2,048의 정상 17개·빈 답변 실패 3개를 원문 그대로 대조군으로 보존합니다. low/2,048과 medium/4,096을 한 변수 비교로 해석하지 않습니다.

## 현재 단계

실제 생성 경로를 구현·검증 중이며 아직 새 답변을 생성하지 않았습니다. 기존 low/2,048 대조군 gate와 기본 CLI는 유지합니다. 새 budget 경로에만 정확히 4,096토큰을 전달하고 기본 2,048토큰 요청 바이트의 동일성을 합성 테스트로 확인합니다.

외부에서 고정한 비교·전체 summary SHA와 원문 답변·행·입력·지침·요청·설정·모델 핀을 호출 전과 실행 중 재검증합니다. 현재 모델 digest가 맞을 때만 문항당 1회·최대 20회를 호출하며 재호출하지 않습니다. 출처나 모델이 바뀌면 남은 호출을 멈추고 이미 시도한 기록·중단·미호출을 별도로 남깁니다. 원래 partial 상태와 실패 3개를 변경하지 않습니다.

새 후보는 설정·시간·토큰을 가린 A/B 패킷에서 Codex가 독립 검토해야 합니다. 실패·빈 답변은 의학적 기준을 임의로 미충족으로 바꾸지 않고 별도 생성 실패 0점 정책으로 구분합니다. 보류를 유지하고 전체 20개를 분모에 포함합니다. 빈 답변 감소와 사실·안전·이력·정보 출처의 품질 개선은 별도로 확인합니다.

서로 다른 시점의 캐시 대조군과 단일 새 실행을 비교하므로 재현성이나 일반적인 인과 효과를 입증하지 않습니다. 전체 시간·토큰·추가 모델 조회도 기록하며, 가능한 기준 점수 범위를 확정 점수나 의료 정답률로 표시하지 않습니다.

고유한 전용 결과 폴더와 한 작성자의 소유 범위를 사용합니다. mkdir과 최초 inode 확인 사이 같은 UID의 빈 폴더 교체는 완전히 배제하지 못하는 문서화된 한계가 있으며 모든 동시 변경을 차단한다고 주장하지 않습니다.
