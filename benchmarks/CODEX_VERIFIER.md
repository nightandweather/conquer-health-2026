# Codex가 검증하는 답변 개선 과정

gpt-oss는 답변을 생성하고, Codex는 답변과 실제 대화 이력을 독립적으로 검증합니다.
Codex가 개발 실패를 분석해 일반 지침을 바꾸면 gpt-oss가 새 답변을 생성하며,
Codex가 그 답변을 다시 검토합니다. 모델이 자신의 답변에 붙인 점수나 자기 검토 통과 여부를
품질 판정으로 사용하지 않습니다.

## 역할과 판정

| 담당 | 하는 일 | 남기는 증거 |
|---|---|---|
| gpt-oss | 원래 입력과 고정 지침으로 답변 생성 | 답변, 요청 해시, 종료 상태, 전체 시간·토큰 |
| Codex 검증자 | 원문과 기준을 대조하고 의심되는 사실은 원 논문·공식 지침 확인 | 기준별 충족/미충족/보류, 근거, 오류 위치 |
| Codex 개선 담당 | 개발용 실패 유형을 일반화해 지침 또는 이력 처리 한 가지 수정 | 지침 버전·해시, 수정 이유, 사용한 개발 범위 |
| Codex 재검증자 | 설정을 가린 이전 답변과 새 답변 비교 | 해결된 오류, 새 오류, 불확실한 차이 |

검토에서는 사실의 정확성, 요청 충족, 안전상 중요한 누락, 근거 없는 환자 정보,
이력의 모순, 불필요한 반복 질문, 읽기 편한 표현을 확인합니다. 기준 점수만으로
중대한 오류를 지우지 않으며, 보류 항목은 자동으로 성공이나 실패로 채우지 않습니다.
공식 HealthBench 점수나 의료 전문가의 검증으로 표시하지 않습니다.

판정용 패킷에는 원래 입력·기준·익명 답변만 넣고 설정 이름·시간·토큰은 가립니다.
검증자는 개선 담당자가 의도한 결론을 전달받지 않습니다. 개발 실패를 이미 읽은 사람이
최종 평가까지 혼자 담당하는 경우에는 그 한계를 기록합니다.

## 반복 절차

1. 현재 기본·grounded-v2의 200문항 실행을 고정한 채 완료합니다.
2. Codex가 개발용 20문항의 두 답변을 검토합니다. 현재 40답변의 기준별 검토가 있으며,
   보류 판정은 근거를 더 확인합니다.
3. 실패 유형을 보고 일반 지침을 수정합니다. 실제 질문, 정답, 기준 문구, 문항별 피드백을
   생성 모델의 입력에 복사하지 않습니다.
4. `healthbench_codex_cycle`로 같은 개발 20문항만 재생성합니다. 마지막 user 턴에 지침을
   붙이는 위치와 temperature 0·low·2,048토큰·1호출 조건을 유지합니다.
5. Codex가 원래 grounded-v2와 새 후보를 다시 검토합니다. 새 후보가 잘렸거나 중요한
   오류를 만들면 그 사실을 남깁니다. Codex가 답변을 직접 고쳐 대체하지 않습니다.
6. 품질 차이를 먼저 확인하고 전체 시간과 토큰을 비교합니다. 개선이 확인되지 않으면
   채택하지 않고 개발 범위 안에서 다음 가설을 검증합니다.

평가용 180문항의 답변은 프롬프트 개선의 근거로 사용하지 않습니다. 후보를 확정한 뒤
그 버전으로 별도 평가하며, 독립 평가에 사용한 실패 유형으로 다시 튜닝하면 그 자료는
이후의 독립 평가셋으로 취급하지 않습니다. 현재의 200문항 실행은 새 지침으로 바뀌지 않습니다.

첫 후보는 [codex_guided_v3.txt](prompts/codex_guided_v3.txt)입니다. 개발 검토에서 발견한
근거 없는 사실, 과도한 단정, 중요한 누락을 줄이도록 일반 지침을 작성했습니다.
실제 생성과 독립 재검토를 완료했으며, 품질 향상은 확인되지 않아 채택하지 않았습니다.

```sh
python3 -m benchmarks.healthbench_codex_cycle \
  --data private_data/healthbench/legacy_consensus_val_roles.json \
  --baseline-manifest results/BASELINE_RUN/manifest.json \
  --instructions-file benchmarks/prompts/codex_guided_v3.txt \
  --candidate-name codex_guided_v3 --instructions-version 3 \
  --out results/codex-guided-dev20-prepared --prepare-only
```

준비 모드는 모델을 호출하지 않습니다. 실제 생성은 기준선 완료 뒤 새 출력 폴더에
`--prepare-only` 없이 실행합니다. 생성만 끝난 결과에는 점수를 붙이지 않으며,
Codex의 기준별 판정과 답변 해시가 일치하는 검토 결과가 있어야 점수를 계산합니다.
이 CLI가 Codex 채점 API를 자동 호출하는 기능은 없습니다.

기준선 완료를 기다린 뒤 한 번 실행하고 검토 패킷까지 준비하려면:

```sh
python3 scripts/run_codex_cycle_after_baseline.py \
  --data private_data/healthbench/legacy_consensus_val_roles.json \
  --baseline-manifest results/BASELINE_RUN/manifest.json \
  --instructions-file benchmarks/prompts/codex_guided_v3.txt \
  --candidate-name codex_guided_v3 --instructions-version 3 \
  --out results/codex-guided-v3-queue
```

큐는 고정 기준선의 조건·자료·지침이 유지되는지 확인하고, 완료 후 `candidate/`에
개발용 답변을 생성합니다. `comparison/`에는 원래 grounded 답변과 새 후보를 이름 변경
없이 보존하고 출처 해시를 남깁니다. `comparison/review/`의 A/B 패킷을 Codex가 검토해야
품질 판정이 생깁니다. 기준선 실패·중단이나 조건 변경은 새 호출을 시작하지 않습니다.

개발 20문항의 기존 답변 40개에는 86개 기준별 판정이 있습니다. 이 개발 자료의
가중 기준 점수 평균은 기본 20.83%, grounded-v2 50.00%입니다. 같은 조건에서 지침만
바꾼 비교는 아니며, 복구된 자료·Codex 판정·작은 개발 범위의 진단값입니다.
채점 기준과 별도로 의료 오류·누락을 표시했고 역방향으로 작성된 기준도 따로 기록했습니다.
후속 후보 검토는 아래에 따로 기록합니다. 재검토자가 같은 대조군에 붙인 판정에도
차이가 있어 기존 개발 점수와 후속 후보 점수를 그대로 빼서 개선량으로 사용하지 않습니다.

## 개발 반복의 범위와 중단 조건

첫 개발 반복은 후보 지침 최대 3개로 제한합니다. 이는 실행 전에 고정하는 시작 정책이며
최적 반복 횟수라는 뜻은 아닙니다. 각 후보는 개발 20문항에 한 번씩 호출하고, Codex의
독립 검토가 끝나기 전에는 다음 후보를 생성하거나 자동으로 채택하지 않습니다.
프롬프트 변경은 Codex가 개발 실패를 일반화해 작성하며, Python 실행기가 스스로 새
지침을 만들거나 gpt-oss의 자기 점수로 합격시키지 않습니다.

비교 기준은 동일 설정의 기존 `grounded_call`입니다. 이전 후보보다 나아졌는지도
별도로 기록하되, 매번 처음의 대조군을 유지합니다. 한 번에 일반 지침, 이력 처리,
추론 설정 중 하나를 바꿉니다. 첫 후보에서는 지침만 바꾸고 이력과 호출 설정을 유지합니다.

- 20개 비교의 기준별 검토가 모두 끝나고 보류가 없어야 채택을 검토합니다.
- 점수가 올라도 새 중대한 오류, 정보 출처의 혼동, 필요한 내용의 누락이 생기면
  채택을 멈추고 원인을 확인합니다. 문제 있는 채점 기준에 맞추기 위해 답변을 왜곡하지 않습니다.
- 연속 두 후보에서 품질 개선이 확인되지 않으면 같은 개발셋의 반복을 중단합니다.
- 품질이 같으면 시간·토큰 절감을 따로 검토합니다. 실패·잘림·빈 답변·재호출도 함께
  기록하고, 단일 실행의 시간 차이를 확정적인 속도 개선으로 표현하지 않습니다.
- 후보를 고정한 뒤에만 평가용 180문항을 비교합니다. 그 개별 실패를 다음 지침에
  사용하면 그 자료는 이후의 독립 평가셋이 아닙니다.

각 회차에는 원본 실행 상태와 해시, 선택한 대조군 행의 해시, 지침 버전·해시, 모델 digest,
검토 근거, 채택 또는 기각 이유, 시간·토큰·잘림·실패를 남깁니다. 생성 실패나 연결 차단도
회차 결과로 보존하며, 원본 답변을 Codex가 고친 문장으로 대체하지 않습니다.

### 부분 완료 실행에서 개발 대조군만 검증

400회 생성은 종료됐지만 기본 답변 1개가 실패하여 원본 실행은 `partial`입니다.
원본 상태를 바꾸지 않고, 명시적인 `--allow-finalized-dev-control` 옵션으로 종료된 실행의
개발용 `grounded_call` 20개만 검증할 수 있습니다. 전체 원본 행·집계·출처의 무결성과
선택한 대조군의 정상 완료·원문 요청·고정 설정·모델 일치를 확인합니다. 원본이 실행 중이거나
선택한 대조군이 누락·실패·잘림 상태이면 이 경로도 거부합니다.

```sh
python3 scripts/run_codex_cycle_after_baseline.py \
  --data private_data/healthbench/legacy_consensus_val_roles.json \
  --baseline-manifest results/healthbench-live-20261011-045938-5bd962/manifest.json \
  --instructions-file benchmarks/prompts/codex_guided_v3.txt \
  --candidate-name codex_guided_v3 --instructions-version 3 \
  --allow-finalized-dev-control \
  --out results/codex-guided-dev20-v3-ROUND_ID
```

`ROUND_ID`는 새 회차마다 고유한 값으로 바꿉니다. 위 실행은 생성과 익명 비교 패킷을 만들며,
Codex 재검토·채택 판정은 후속 단계입니다. 준비 모드는
`benchmarks.healthbench_codex_cycle --prepare-only`로 모델 호출 없이 입력을 확인합니다.
네트워크 승인 후 첫 후보 20문항을 20호출로 정상 생성했습니다. 생성은 131.479초였으며,
같은 20개 대조군의 요청 시간 합은 114.210초, 후보의 요청 시간 합은 130.977초입니다.
40개 익명 답변의 독립 검토에서는 84개 기준 판정과 2개 보류를 기록했습니다. 원문 입력을
넘어선 사실과 치료 제안을 추가한 오류가 있어 후보를 채택하지 않았습니다. 보류는 별도
감사했지만 두 항목 모두 보류를 유지했습니다. 점수가 있는 답변만 골라 전체 20문항의
개선으로 표시하지 않습니다.

두 번째 후보는 [codex_guided_v4.txt](prompts/codex_guided_v4.txt)입니다. 첫 후보의 개발 오류를
일반화해 요청에 직접 답하고 불필요한 치료·검사 목록을 줄이는 지침을 앞에 두었습니다.
환자 사실 보존과 불확실성 처리는 유지합니다. 실제 문항, 정답, 질병·약 이름이나 기준
명제를 지침에 복사하지 않았고 호출 설정과 이력·지침 위치는 그대로 둡니다.
두 번째 후보도 20호출·20정상 답변으로 생성하고 40개 익명 답변의 독립 검토를 완료했습니다.
78개 기준 판정과 8개 보류가 남았고 새로운 사실·안전 쟁점이 있어 채택하지 않았습니다.
연속 두 후보에서 정확도 개선을 확인하지 못해 정한 정책에 따라 반복을 중단했습니다.

| 개발 후보 | 신규 호출 | 정상/잘림/실패 | 생성 전체 시간 | 요청 시간 합 | 신규 호출 총 토큰 입력과 출력 | 보류 기준 |
|---|---:|---|---:|---:|---:|---:|
| v3 | 20 | 20/0/0 | 131.479초 | 130.977초 | 22,407 | 2 |
| v4 | 20 | 20/0/0 | 59.494초 | 58.953초 | 14,356 | 8 |

같은 개발 대조군의 요청 시간 합은 114.210초, 토큰 합은 18,027입니다. 단일 실행의
시간·토큰 관측이며 품질이 같다는 검증이나 통계적 속도 개선을 의미하지 않습니다.
현재 채택한 후보는 없고 평가용 문항에 새 후보를 호출한 횟수는 0입니다.

### 원래 200문항 전체 검토와 보류 범위

생성이 종료된 원래 200문항의 두 답변을 추가 모델 호출 없이 모두 검토했습니다. 후보 지침을
고정한 이후에 진행하며, 평가용 개별 오류는 새 지침 작성에 사용하지 않습니다.
이 검토는 원래 두 설정의 진단이며 채택하지 않은 후보의 평가가 아닙니다.

기본 답변의 기록된 실패 1건 때문에 기본 패킷은 199개입니다. 전체 검토에서는 새 비공개
출력 폴더에 원본 답변·manifest 바이트를 그대로 복사하고, 종료 상태와 선택된 실패
시도의 증거가 맞을 때만 `--include-known-inference-failures`로 실패 쌍까지 포함합니다.
기존 199개 패킷은 바이트 단위로 동일하며 원본 `partial` 상태는 바꾸지 않습니다.
실패 답변은 사전 정의한 생성 실패 점수 0으로 남기고, 없던 의학적 기준 판정은 만들지 않습니다.
나머지 답변의 보류 기준은 계속 미판정으로 남습니다.

이 경로는 전체 원본 답변 파일의 처음 SHA를 재생성·export에서 확인합니다. 모든 실패
분류 행에 선택 시도의 증거를 검증하고, 증거 없는 실패·빈 정상 답변·실패 별칭을 거부합니다.
성공하거나 잘린 답변을 버리고 실패를 선택한 행과 실패 증거의 사후 변경도 거부합니다.
기본 실행 중 패킷을 추가하는 경로의 바이트와 동작은 유지합니다.

검토 exporter는 `score_summary.json`과 `score_bounds.json`을 따로 만듭니다. 보류가
있으면 전체 확정 점수는 비워 두고, 각 보류 기준이 충족/미충족일 때 가능한 점수의
하한·상한을 계산합니다. 음수 기준 가중치와 평균 후 제한을 적용하며, 이 범위는
실측 점수나 신뢰구간이 아닙니다. 답변 누락·실행 차단이 있으면 범위도 계산하지 않습니다.

최종 검토는 200개 패킷·400개 기록이며, 834개 Boolean 판정과 40개 보류를 남겼습니다.
실패 답변의 2개 기준은 판정하지 않고 생성 실패 0점으로만 처리했습니다. 359개 답변은
기준 점수가 있고 실패 1건은 0점, 40개 답변은 점수 미정입니다. 따라서 전체 확정 점수는
없으며 아래는 보류 판정에 따른 가능한 범위입니다.

| 검토 범위 | 문항 수 | 기본 호출 가능 점수 | 사실 보존 지침·low 호출 가능 점수 |
|---|---:|---:|---:|
| 전체 | 200 | 20.83–25.17 | 50.33–54.92 |
| 평가용 | 180 | 20.83–25.65 | 50.37–55.46 |
| 기존 이력 있음 | 81 | 19.55–25.51 | 53.70–59.05 |
| 단일 질문 | 119 | 21.71–24.93 | 48.04–52.10 |

100점 척도의 기준 점수 범위입니다. 의료 정답률이나 공식 HealthBench 점수가 아닙니다.
기본과 지침 설정은 추론·temperature도 달라 지침만의 효과로 해석하지 않습니다.
두 설정의 요청 시간 합은 각각 3,229.667초와 1,159.832초, 총 토큰은 328,533과
178,452입니다. 기존 두 설정의 관측이며 신규 v3/v4 후보의 평가 결과가 아닙니다.
기준 점수와 별도로 사실·안전·이력·누락·가독성·기준 자체의 쟁점을 보관했습니다.
저장된 복원 이력에 답한 결과이며 새 여러 턴 대화의 개선을 입증하지 않습니다.

## 지속 개선 실행

사용자 요청에 따라 이 대화의 반복 작업을 활성화했습니다. 5분마다 현재 저장소와
진행 기록을 확인하고 미완료 실행·검토부터 이어갑니다. 이전 v3/v4 반복의 미채택 결과는
유지하며 새로운 근거와 다른 가설이 있을 때만 다음 phase를 시작합니다.

매 실행의 신규 후보는 최대 하나, 개발용 최대 20문항에 문항당 1호출입니다. 이전 회차의
독립 검토가 끝나기 전에 다음 후보를 호출하지 않습니다. 한 가설에서 두 후보 연속으로
개선이 확인되지 않으면 그 가설을 종료하고 근거 없는 재실행을 하지 않습니다.
보류 해소와 새 중대한 오류 없음, 비교 가능한 대조군 대비 품질 개선이 채택 조건입니다.
품질이 같을 때만 시간·토큰 절감도 검토합니다. 평가용 180문항의 개별 피드백은 지침이나
설정 수정의 근거로 사용하지 않습니다.

새 추론 설정 phase에서는 원래 grounded-v2 지침·이력·temperature 0·2,048토큰·1호출을 유지하고 추론 설정만 low에서 medium으로 바꿨습니다. 실행기와 큐의 `--reasoning-effort` 전달, 기본 low 동작 보존, 설정·요청 변조 거부를 구현·검증했습니다. [고정 원래 지침](prompts/grounded_v2_frozen.txt)은 끝 개행도 추가하지 않아 입력 해시가 동일합니다.

```sh
python3 -m benchmarks.healthbench_codex_cycle \
  --data private_data/healthbench/legacy_consensus_val_roles.json \
  --baseline-manifest results/healthbench-live-20261011-045938-5bd962/manifest.json \
  --instructions-file benchmarks/prompts/grounded_v2_frozen.txt \
  --candidate-name grounded_medium_v1 --instructions-version grounded-v2 \
  --reasoning-effort medium --allow-finalized-dev-control \
  --out results/UNIQUE_REASONING_ROUND --prepare-only
```

위 예는 호출 없는 준비 모드이며 출력 폴더는 새 회차마다 고유하게 지정합니다. 실제 이번 회차는 개발 20문항·20호출로 종료됐고 정상 17개·빈 답변 실패 3개입니다. 실패는 length 종료·2,048 출력 토큰으로 기록했고 재호출하지 않았습니다. 설정을 가린 새 독립 검증자 두 명이 40개 기록을 모두 검토했습니다. 기준 판정 76개를 확정하고 4개를 보류했으며 실패 답변의 6개 기준은 생략했습니다. 이번 기준 점수 범위는 높아졌지만 새 안전 오류·실패 3건·보류로 채택하지 않았습니다. [이번 추론 비교 기록](REASONING_EFFORT_DEV20.md)에 생성 시간·토큰·검토 상태와 미채택 이유를 기록합니다. 기존 v3/v4 종료 결과와 원래 200문항 검토는 별도로 유지합니다.

검증한 코드·일반 지침·합성 테스트·공개 가능한 집계와 미채택 이유도 기존 개발 브랜치에 커밋·푸시하고 비교 화면과 기존 PR을 갱신합니다. 실제 자료·답변·기준·환자 정보·키·개별 근거는 로컬 비공개 결과에 보관합니다. NOVA SDK 지원과 실제 여러 턴 동작의 개선은 별도 검증하며 아직 이 설정을 제출 에이전트에 적용하지 않았습니다.

### 보류의 독립 재확인

직전 추론 비교의 보류 4개는 새 독립 검증자의 추가 확인에서도 모두 보류로 유지했습니다. 원문 기준의 판정 방향·적용 조건·근거 정의가 명확해져야 다시 판정할 수 있습니다. 원래 자료를 임의로 고쳐 판정하지 않고, 보류와 미채택 상태를 유지합니다. 같은 자료의 재판정은 새 근거가 있을 때만 진행합니다. 직전 준비 회차의 새 생성 호출은 0회였습니다.

출력 예산의 후속 회차는 기존 medium/2,048 대조군을 보존하고 medium/4,096과 `max_tokens`만 비교했습니다. [준비 검증 설계](BUDGET_CONTROL_PREFLIGHT.md)는 비교 원본과 source summary의 외부 SHA를 각각 고정하고 20개 원문 요청·실패 증거를 확인합니다. 별도 budget 경로의 합성 검사와 독립 감사를 통과한 뒤 한 번씩 호출했고 정상 18개·빈 답변 실패 2개로 종료했습니다. 원래 정상 답변 17개는 그대로이며 새 검증자 두 명이 40개 기록을 검토했습니다. 기준 판정 70개·보류 6개이고 실패 답변의 10개 기준은 생략했습니다. 두 설정의 가능한 기준 점수 범위는 모두 56.67–63.33이며 회복된 답변도 기준 점수 0입니다. 새 중대한 의학적 오류·잔여 빈 답변 2개·보류로 채택하지 않았습니다. [실제 출력 한도 비교](OUTPUT_BUDGET_DEV20.md)에 전부 기록합니다. 기존 low 대조군 gate와 일반 CLI의 2,048토큰 기본 동작은 유지합니다.

## 여러 턴의 검증

HealthBench의 복원 이력에서는 이전 assistant의 주장을 환자 사실로 취급하는지,
이미 나온 정보와 새 답변이 모순되는지, 답할 수 있는 질문을 반복해서 되묻는지 확인합니다.
새 대화를 만들 때는 사용자가 보고한 정보, 실제 도구 결과, 모델의 가설을 출처와 턴으로
구분합니다. 검증자의 지적은 환자의 새 발화로 삽입하지 않습니다.

실제 문진·진찰에서 질문의 적절성, 반복 행동, 중대한 정보 누락, 최종 기록의 사실 보존은
NOVA 공개 샘플의 실제 응답과 행동 기록으로 별도 검증합니다. 복원된 HealthBench
이력만으로 새로운 여러 턴 대화가 좋아졌다고 결론 내리지 않습니다.

기존에 저장된 NOVA 공개 샘플 3건의 84턴도 Codex가 정성 검토했습니다. 수치·개수·시간의
기록 변형, 미확인 항목의 사실화, 반복 질문과 요청/반환의 불일치를 검토 쟁점으로 남겼습니다.
시뮬레이터의 기본 진찰 응답을 실제로 받은 경우에는 그 응답을 옮긴 행위와 환경의 근거
한계를 구분합니다. 임상 정확성·공식 점수·시간 절감량은 판정하지 않았고 실제 대화와
검토 근거는 로컬에 보관했습니다.

Codex는 이 개발 과정의 외부 검증자입니다. 제출 에이전트가 실행 중 Codex를 호출하는
구조를 추가한 것은 아닙니다. gpt-oss의 자기 검토는 비교할 수 있는 보조 실험으로 보관하며,
기준선 뒤 자동 실행을 기다리던 자기 검토 큐는 이 검증 절차로 전환하면서 생성 전 종료했습니다.

공식 일반 채점 정의도 확인했습니다. `criteria_met`는 문구상 기준 충족 여부이며 답변의 좋고 나쁨을 직접 표시하지 않습니다. 음수 배점의 바람직하지 않은 행동이 없으면 false가 될 수 있고, 충족된 기준의 배점을 합산합니다. [공식 grader와 점수 함수](https://raw.githubusercontent.com/openai/simple-evals/main/healthbench_eval.py). 일반 정의만으로 문구·배점·요구 방향이 모순되는 개별 기준을 고치지 않습니다. 해당 기준의 공식 정정 근거가 없어 이전 보류와 원문 판정은 유지하며, 그 기준만 반복 재배정하지 않습니다.

[고정 지침의 전달 위치 개발 실험](INSTRUCTION_PLACEMENT_DEV20.md)은 같은 medium/2,048에서 원래 지침 블록을 last-user 부록에서 API system 메시지로 옮겼습니다. 20개 신규 호출은 정상 18·빈 답변 실패 1·잘림 1이며 로컬 모델·템플릿 핀도 일치했습니다. 새 독립 검토는 기준 판정 76개·보류 2개, 실패의 8개 기준 생략입니다. 가능한 기준 범위는 대조군 57.50–59.17, 후보 59.17–60.83으로 맞닿지만 전체 품질 우위를 확정하지 못했고 새 중대한 안전·환자 정보 오류로 미채택했습니다. 시간 8.32%·총 토큰 2.72% 감소는 단일 실행 관측이며 기존 보류를 해소하거나 공식 점수를 만든 결과가 아닙니다. 준비·생성·내용 검토를 별도로 보관합니다.

[사용자 원문 출처 색인 실험](SOURCE_LEDGER_DEV20.md)은 호출 없는 준비 뒤 별도 고정 실행기로 20문항을 한 번씩 생성했고 모두 비어 있지 않은 완료 답변을 받았습니다. 원래 대조군의 정상 18·빈 실패 1·잘림 1과 partial 상태를 보존합니다. 새 독립 검토 40기록은 기준 판정 78개·보류 6개, 실패의 2기준 생략이며 기준 점수 34기록·별도 실패 0점 1기록·점수 보류 5기록으로 구분합니다. 가능한 범위는 대조군 49.17–57.50·후보 50.83–55.00으로 겹치고 새 중대한 약물 정체성 오류와 전체 품질 향상 미확인으로 미채택했습니다. 이전 판정은 유지하고 같은 후보를 다시 호출하지 않습니다. 요청 시간 3.93%·총 토큰 4.38% 증가는 단일 실행 관측입니다. 새 모델 정보·템플릿 조회는 각각 43회이며 생성과 별도입니다. private 전체 372개·공개 지정 11개 모듈 249개·새 실행기 합성 25개 검사와 독립 코드 감사가 통과했습니다. 사용자 발화의 출처 표시를 환자 사실의 진실성이나 의학적 정확성으로 인증하지 않습니다.
