# 200문항 답변 품질 비교

목표는 정확하고 필요한 내용을 갖춘 답변을 적은 시간과 토큰으로 만드는 것입니다.
짧은 출력, `stop` 종료, 빠른 생성만으로 품질 향상을 판정하지 않습니다.

## 고정한 비교 조건

- 동일한 로컬 `gpt-oss:20b`와 동일한 200문항에 기본 호출과 사실 보존 지침을 적용합니다.
- 루닛 호출은 앞선 3문항 비교를 보관합니다. 전수 실행은 두 설정, 총 400개 답변입니다.
- 정렬순 앞 20문항은 개발용, 뒤 180문항은 평가용입니다. 먼저 읽은 3문항은 개발용에 포함됩니다.
- 200문항 실행을 시작하기 전에 지침을 고정합니다. 평가용 답변을 본 뒤 제안하는 변경은
  후속 실험의 후보이며, 이 실행의 평가용 결과를 보고 지침을 바꾸지 않습니다.
- 기본 호출은 서버의 기본 추론 설정을 사용합니다. 개선 호출은 `temperature=0`,
  `reasoning_effort=low`, 최대 2,048토큰입니다. 두 설정 모두 한 번 호출합니다.
  따라서 이 비교는 지침과 호출 설정을 함께 바꾼 결과입니다.

## 대화 이력

원본 아카이브의 81문항에는 `user: `, `assistant: ` 역할 표식이 있는 이력이 있습니다.
명확한 표식을 엄격하게 검증하고 원문 본문을 보존해 메시지로 복원합니다.
교대 순서가 잘못되거나 표식이 모호하면 변환을 거부합니다. 새 환자 사실이나 요약을
임의로 추가하지 않으며, 이전 assistant의 주장을 확인된 환자 사실로 취급하지 않습니다.
두 호출에 같은 메시지 이력을 전달하고 채점 기준은 생성 모델에 전달하지 않습니다.

복원 전과 후의 자료는 별도 파일과 해시로 남깁니다. 원본 HealthBench ID가 없는
재구성 자료이므로 공식 HealthBench 점수와 직접 비교하지 않습니다.

NOVA의 후속 에이전트에는 다음 구분을 검토합니다. 아직 이번 실행에 구현하지 않았습니다.

1. 사용자 답변과 실제 검사 결과: 출처·턴을 갖는 확인된 사실.
2. 모델의 추정: 가능성으로 표시한 가설, 확인된 사실로 승격하지 않음.
3. 미확인 정보: 다음 질문 또는 검사에서 확인할 항목.
4. 행동 기록: 질문·검사·결과를 원문으로 보관하고 반복 행동을 방지.

## Codex 품질 검토

저장된 두 답변을 A/B로 가리고 문항별 원래 기준에 따라 Codex가 판정합니다.
생성 설정, 시간, 토큰 수는 검토 패킷에 넣지 않습니다. 기준마다 충족/미충족과
짧은 근거를 기록하고, 근거가 부족한 항목은 판단 보류로 남깁니다.
의학적 사실이 의심되면 원 논문이나 공식 가이드라인으로 확인합니다.
이 검토는 공식 HealthBench 채점 모델의 결과가 아닙니다.

판정이 모두 있는 답변에만 원래 가중치로 점수를 계산합니다. 보류 항목을 자동으로
실패나 성공으로 채우지 않고, 평가 완료 비율도 함께 기록합니다. 생성 실패는 별도로
보고합니다. 사실 오류·근거 없는 환자 정보·중요한 누락은 점수와 함께 따로 표시합니다.

개발 20문항과 평가 180문항, 이력이 있는 문항과 단일 질문 문항을 각각 집계합니다.
품질 차이를 먼저 확인하고, 같은 문항에서의 시간·토큰·출력 잘림·재호출을 비교합니다.
실험 코드와 집계 결과는 Git에 커밋하고 원문 자료·답변·검토 근거는 로컬에 보관합니다.

점수식은 [OpenAI HealthBench 구현](https://github.com/openai/simple-evals/blob/main/healthbench_eval.py)의
기준 충족 점수 합 / 양수 기준 점수 합과 문항별 평균을 사용합니다.
