# 이미 제공한 답변의 재사용 — HBT03 미실행 설계

2026-10-12. **설계만 저장했으며 새 실행 코드·모델 호출·NOVA 제출은 모두 0이다.** [HBT01](HEALTHBENCH_TURN_PROBE.md)의 기존 독립 검토가 특정한 두 첫 답변에서, 사용자에게 이미 들은 사실을 복합 질문의 일부로 다시 물었다. 다음 후보는 질문을 내보내기 전에 이미 제공된 답과 대조하라는 지시 하나를 시험하도록 설계했다. [HBT02](HEALTHBENCH_CARE_TIMING_PROBE.md)는 4회 소진·3완전·1빈 답변 한도 종료·임상 비교 미수행·미채택 상태로 보존한다.

## 선택 근거와 변경

검사 이유가 후속 질문 뒤 등장한 3건이라는 집계는 첫 답변에서 권고한 검사 이유를 3건 빠뜨렸다는 뜻이 아니다. 첫 답변에 검사 제안 자체가 없거나 조건부 제안만 있었고, 일반적인 진료 목적 설명이 이미 있는 경우도 있었다. 그 분류를 오류로 재판정하지 않았으며, 검사 이유 후보는 현재 근거로 선택하지 않았다.

기존 프롬프트에는 필요한 정보만 질문하고 불확실성을 유지하라는 지시가 있다. 새 후보는 질문의 각 부분을 이미 제공된 사용자 답과 대조하는 규칙을 명시한다. 원래 HBT01 system 끝에 다음 지시 묶음만 두 줄 간격으로 덧붙일 계획이다.

> Before asking a question, check whether the user has already clearly answered it. Re-ask only to resolve ambiguity, conflicting information, or a relevant change over time, and make that reason explicit.

HBT02 진료 시점 지시는 상속하지 않는다. 별도 사실 요약, 검색, 추가 검토 호출, 출력 예산이나 종료 턴 변경은 없다. 문장이 늘어나므로 토큰·시간·답변 길이·실패 여부가 같다고 가정하지 않는다.

## 비교 범위와 비용

기존 HBT01 개발 입력 네 개의 첫 응답 직전 요청을 고정한다. 두 개는 이미 확인한 재질문 관찰 대상, 두 개는 필요한 확인과 안내가 보존되는지 보는 대상이다. 네 입력 각각에 새 답변 한 번만 계획하며, 재시도·후속 대화 진행·환자 모델·자동 채점 API는 0회다. 원래 저장 답변을 비교 대상으로 사용하고 대조군은 다시 생성하지 않는다.

모델은 로컬 gpt-oss:20b, medium, temperature 0, 출력 한도 2,048토큰, 요청별 timeout 90초를 유지한다. 네 요청의 설정상 출력 한도 합은 8,192토큰, timeout 합은 360초이며 실제 요청 시간이나 전체 작업 완료 시간을 보장하지 않는다. 입력·실제 출력 토큰과 금전 비용은 아직 측정하지 않았다. 별도 유료 생성 endpoint는 추가하지 않으며 로컬 전력·하드웨어와 Codex 검토 사용량은 별도다. 이번 설계에서는 실행 중인 모델 신원을 새로 조회하지 않았다.

후속 환자 요청·수정 답변·기존 검토문과 HBT02 답변을 후보 입력에 넣지 않는다. 평가용 180개와 원래 채점 기준·답변도 사용하지 않는다. 고정 요청의 첫 system 추가 외 모든 필드를 보존한다. 원본에 과거 assistant 내용이 있더라도 확인된 환자 사실로 승격하지 않는다. RAG·NOVA SDK·30자 행동 제한이 없는 로컬 비교다.

## 판정 조건

새 독립 검토자는 원래 맥락과 익명 A/B 답변을 읽되 가설·지시·설정·시간·토큰·기존 검토를 보지 않는다. A/B 순서는 생성 전에 고정한다. 이번 설계 비판자는 그 임상 비교 검토자를 맡지 않는다.

- 두 관찰 대상에서 이미 답한 질문 부분을 줄이되, 복합 질문의 아직 모르는 부분은 유지해야 한다.
- 모호함·정보 충돌·의미 있는 상태 변화 때문에 재확인이 필요하면 이유를 밝혀도 된다. 미래 경고 증상을 조건부로 안내하는 것은 재질문으로 세지 않는다.
- 질문을 모두 없애거나 답을 지어내서 통과할 수 없다. 사용자 보고·과거력·음성 답변을 현재 검사 결과나 확정 진단으로 바꾸지 않아야 한다.
- 필요한 확인, 진료 계획과 즉시 행동 안내를 보존해야 한다. 질문 개수 감소만으로 성공을 판정하지 않는다.
- 새 중대한 안전 문제나 해소되지 않은 핵심 판단이 있으면 채택 단계로 진행하지 않는다. 새 의학적 불확실성은 공식 근거로 확인하거나 null로 남기며, 기존 보류 판정을 새 근거 없이 반복 재심하지 않는다.

네 답변이 모두 완전·비어 있지 않음·호출 후 핀 일치 조건을 충족해야 맹검 자료를 내보낸다. 빈 답변·잘림·실패·미확정 전송은 별도로 보존하고 성공 사례만 골라 평가하지 않는다. 재시도, 다른 출력 폴더, 예산 변경, 사례 교체나 판정 조건 완화로 같은 후보를 구제하지 않는다. 같은 후보 재호출 금지와 같은 가설 두 번 실패 후 중단 규칙을 유지한다. 이 가설은 아직 실행 0회다.

## 실행 전 남은 작업과 한계

별도 실행기와 영구 호출 예약, 요청 차이·출처·모델·템플릿 핀·대상 답변 비노출 합성 검사 및 독립 감사가 필요하다. HBT01/HBT02 실행 이력과 E05 코드·ZIP은 불변으로 보존한다. 이 문서는 요청을 전송하지 않으며 NOVA 제출로 이어지지 않는다.

이미 관찰한 개발 사례를 사후 선택하고 역사적 대조군과 사례당 한 번만 비교하는 설계다. 통과해도 특정 맥락의 재질문 회귀 확인만 가능하며 인과 효과·전체 여러 턴 성능·치료 지식 개선·임상 안전·공식 점수를 입증하지 않는다. NOVA E04/E05 점수의 원인으로 연결하지 않는다. 일반 설계는 [JSON](HEALTHBENCH_QUESTION_REUSE_DESIGN.json), 비공개 고정 요청 참조와 감사는 `results/codex-healthbench-question-reuse-design-v1/`에 저장한다.
