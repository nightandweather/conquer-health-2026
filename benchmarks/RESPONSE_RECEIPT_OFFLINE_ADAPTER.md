# 응답 관측 오프라인 어댑터 — 합성 검증 완료

2026-10-13 KST. [사전 연결 설계](RESPONSE_RECEIPT_INTEGRATION_DESIGN.md)에 따라 **등록된 가짜 응답만 처리하는 별도 어댑터**를 구현했다. 기존 HBT 실행기와 NOVA 런타임에는 연결하지 않았다. 새 실제 모델·제공자 HTTP·메타데이터/템플릿 조회·임상 재검토·NOVA 제출·맹검 export는 모두 0이다. 실제 과거 답변도 다시 처리하지 않았다.

## 저장 순서와 중단 처리

고정 owner/fixture·소스 확인 → 독점 예약 → 전송 가능성 표식 → fake 호출 최대 1회 → 구조 영수증 저장 → **같은 원래 객체**를 parser stub에 전달 → 후속 핀 모의 확인·완료 영수증 → 완료 저장 이후 commit 연결 순서다. 전송 가능성 표식은 실제 호출이나 수신의 증명이 아니다.

객체 관측, 구조 저장, parser 진입, 완료 저장과 의미 결과를 따로 기록한다. 구조 저장 실패는 parser 진입을 막으며 제공자 미응답이나 임상 실패로 합산하지 않는다. 가능하면 정제한 실패 영수증을 저장하고, 그것도 실패하면 기존 디스크 증거에서 확인할 수 없는 상태는 unknown/null로 남긴다. 예약 후에는 호출 카운터가 0이었던 중단 시험에서도 슬롯을 다시 사용할 수 없다. 같은 영구 scope의 다른 출력 폴더로 바꾸는 재진입도 막는다. 부분 파일과 남은 잠금을 자동 삭제하거나 덮어쓰지 않는다.

독립 검토에서 발견한 네 경계를 보완했다. 완료 영수증 자체의 true 값으로 저장 완료를 증명하지 않고, 그 파일의 저장 장벽이 끝난 뒤 별도 commit으로 연결한다. 후속 핀 불일치 기록 자체가 다음 호출을 막으므로 별도 차단 파일 저장 실패에 의존하지 않는다. JSON의 boolean/integer/float를 구분하고, 고정 가짜 응답과 모순되는 complete 표시는 합성 적격 판정을 열 수 없다.

## 검증 범위와 실행량

**고유 검사 20개**가 private/public 각각 지정 모듈 1개에서 통과했다. 기존 설계의 14개 검사군과 보완 회귀 6개이며 전체 검사 실행은 아니다. 두 저장소에서 같은 검사를 실행한 것을 40개 고유 검사로 합산하지 않는다.

| 최종 확인 | 검사 | 명시적 장애주입 | fake 호출 | pipeline helper / parser | 네트워크 시도 |
|---|---:|---:|---:|---:|---:|
| private 지정 모듈 | 20 통과 | 42 | 103 | 98 / 90 | 0 |
| public 동일 사본 | 20 통과 | 42 | 103 | 98 / 90 | 0 |

42건은 고정 `Fault` 주입을 실제로 받은 호출/이벤트 수다. 별도 변조·동시 진입·개인정보 검사 및 monkeypatch로 주입한 복합 저장 실패를 모두 합친 수가 아니다. 예약·표식·구조·완료의 네 저장 단계마다 short write, flush, 파일 fsync, 디렉터리 fsync, interruption을 확인했고 commit 중단, 실패 영수증까지 저장할 수 없는 경우, 중복·다른 출력 폴더·동시 writer·남은 잠금·symlink·부분 파일·핀/해시 변조도 다뤘다.

작성자의 개발 재실행 3회는 각각 18/19/20 검사와 75/79/103 fake 호출이었다. 독립 중간 확인 4건은 fake 10회로 세 경계 통과와 남은 판정 문제를 재현했고, 수정 후 좁은 확인 2건은 fake 8회로 통과했다. **기록된 모든 개발·최종 확인·독립 확인의 fake 호출 합은 481회**다. 이것은 실제 모델 호출이 아니며, 재실행이나 독립 확인을 고유 검사 20개에 더하지 않는다. pipeline helper/parser 수에는 복구 시 수행하는 순수 fixture 정합성 비교가 포함되지 않는다.

최종 private/public 모듈 실행 시간은 각각 0.837175/0.844241초다. 구현·독립 검토·게시를 포함한 전체 작업 시간이 아니다. 검사는 socket/urllib 호출 진입점을 차단했으며 실제 시도 0을 확인했다. 운영체제 전체 네트워크 격리나 실제 전원 차단 시험을 수행했다고 주장하지 않는다.

## 관측·공개 한계

어댑터는 구조 메타데이터만 보존한다. 답변 본문, 추론 본문/해시, 예외 문자열·traceback·임의 경로/식별자를 영수증으로 복사하지 않는다. 사용량의 reported/missing/invalid/unavailable 및 effective total 출처는 [기존 helper](RESPONSE_RECEIPT_HELPER.md) 그대로 유지한다. content 해시는 익명화가 아니며 향후 실제 개별 영수증은 비공개여야 한다.

이 parser는 합성 stub이며 기존 실제 parser와 완전히 동등하다는 검증이 아니다. 현재 Transport가 반환 전에 거절하는 응답은 관측 범위 밖이고, 잘못된 가짜 객체를 주입해도 실제 HTTP 관측 범위가 넓어지지 않는다. 저장 순서·fsync 경계 검사는 모든 저장장치의 전원 차단 내구성이나 임의의 코드·증거 전체 변조에 대한 인증을 보장하지 않는다.

기존 HBT/helper 소스·실제 기록과 E05 코드/ZIP 등 지정 **116파일**의 전후 해시가 일치했다. 전체 백업 검증은 아니다. HBT02/HBT03의 원인 미확정, 임상 비교 null·미채택, 소진된 예약과 네 완전 답변 조건을 유지한다. 이 구현은 새 임상 후보, 이전 후보의 구제 또는 자동 NOVA 접수 권한이 아니다.
