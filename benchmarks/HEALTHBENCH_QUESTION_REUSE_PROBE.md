# 이미 제공한 답변의 재사용 점검 — HBT03

2026-10-12. [사전 설계](HEALTHBENCH_QUESTION_REUSE_DESIGN.md)에 따라 기존 개발 입력 네 개의 첫 응답을 한 번씩 생성했다. **완전한 답변 3개와 출력 한도에 도달한 빈 답변 1개가 나왔다.** 네 답변 모두 완전해야 한다는 사전 조건을 충족하지 못해 맹검 임상 비교를 수행하지 않았으며, 후보는 미채택이다. 이미 답한 질문을 줄였는지와 필요한 확인·안전 안내를 보존했는지는 아직 판정하지 않았다.

## 실제 실행

| 항목 | 결과 |
|---|---:|
| 신규 후보 / 원래 개발 입력 | 1개 / 4개 |
| 신규 생성 요청 / 재시도 / 추가 대화 진행 | 4 / 0 / 0 |
| 완전 응답 / 실패 | 3 / 1 |
| 빈 답변 / `length` 종료 | 1 / 1 — 같은 기록 |
| 내용이 있는 잘린 답변 | 0 |
| 미실행 입력 / 미확정 전송 | 0 / 0 |
| 생성 요청 시간 합 | 49.014초 |
| 보고 입력 / 보고 출력 / 기록된 합계 토큰 | 1,879 / 4,363 / 6,242 |
| 사용량 미보고 응답 | 0 |
| 모델 메타데이터 / 템플릿 조회 | 8 / 8 |
| 환자 생성·자동 채점 API / NOVA 샘플·공식 제출 | 모두 0 |


후속 [오프라인 진단](HEALTHBENCH_COMPLETION_DIAGNOSTICS.md)에서 합계 토큰의 직접 보고/계산 출처가 저장되지 않았음을 확인했다. 위 입력·출력 보고값과 합계 수치는 유지하며, 합계의 원래 출처는 미확인이다. 원래 집계 JSON은 당시 기록으로 보존한다.

한 응답에서 최종 내용이 비어 있고 `finish_reason=length`, 출력 사용량 2,048토큰이 함께 보고됐다. 빈 답변 실패와 한도 종료를 두 실패로 합산하지 않는다. 제공자의 출력 사용량에는 추론이 포함될 수 있지만 별도 추론·표시 답변 토큰을 측정하지 않았으므로 정확한 원인을 단정하지 않는다. 시간은 네 생성 요청의 시간 합이며 준비·메타데이터 조회·감사·전체 작업 경과를 포함하지 않는다.

## 변경 범위와 검증

원래 HBT01 첫 system 메시지 끝에 이미 답한 질문인지 확인하고, 모호함·충돌·관련 상태 변화에 따른 재확인은 이유를 밝히라는 지시 묶음만 추가했다. 네 요청 모두 첫 답변 직전으로 고정했으며 나머지 발화와 설정은 유지했다. HBT02 지시와 생성 답변, 교체 대상 답변, 후속 수정 대화와 기존 검토문은 후보 입력에 넣지 않았다.

로컬 gpt-oss:20b, medium, temperature 0, 출력 한도 2,048토큰과 요청별 timeout 90초를 유지했다. 각 요청 전후 소스·모델 digest·템플릿 핀이 모두 일치했다. 기존 dev20의 네 입력만 사용하고 holdout180·원래 채점 기준·답변은 사용하지 않았다. RAG·NOVA SDK·30자 행동 제한은 없다. 새 후보가 전체 여러 턴 대화를 진행한 실험이 아니라, 저장된 첫 응답 맥락에서 답변 한 번씩 생성한 개발 점검이다.

별도 실행기는 고정 실험 폴더 소유 기록과 전송 전 영구 예약을 사용해 중복 호출을 막는다. 네 예약 모두 완료 기록이 있으며 미확정 전송은 없다. A/B 순서는 생성 전에 2:2로 고정했다. 그러나 불완전 응답 때문에 검토 자료 내보내기가 거부돼 맹검 자료 폴더와 새 임상 검토는 생성하지 않았다.

새 합성 검사 23개와 독립 코드 감사가 통과했다. 공개 사본에서도 기존 여러 턴 검사 21개와 새 검사 23개, 지정한 2개 모듈의 총 44개 검사가 통과했다. 전체 검사 모음을 다시 돌린 것은 아니며, 검사 통과는 임상 정확성을 뜻하지 않는다. 원래 HBT01/HBT02 실행 이력과 E05 코드·ZIP을 포함한 지정 44파일의 전후 해시가 일치했다. 이는 해당 파일의 보존 확인이며 전체 저장소 백업을 뜻하지 않는다.

## 판정과 다음 단계

재질문 해결, 필요한 확인·안전 안내 보존, 임상 정확성 비교는 모두 `null`로 유지한다. 성공한 세 답변만 골라 평가하거나 출력 예산·조건·출력 폴더를 바꾸어 이번 후보를 구제하지 않는다. 기존 HBT01의 보류 판정도 변경하지 않았다. 이 후보는 검증된 개선으로 미채택이며 공식 HealthBench·NOVA 점수는 없다.

HBT02와 HBT03은 서로 다른 지시 가설이고 각각 실행 한 번이다. 두 실험 모두 같은 완전 응답 전제를 충족하지 못했으므로, 다음 후보를 호출하기 전에 저장된 메타데이터와 완료 판정·출력 처리 계약을 오프라인으로 점검한다. 빈 답변을 추가 지시의 인과 효과나 NOVA E04/E05 점수의 원인으로 해석하지 않는다. 동일 후보 재호출 금지와 같은 가설 두 실패 뒤 중단 규칙은 유지한다.

사후 선택한 개발 입력과 역사적 저장 대조군이므로 일반 성능·인과 효과·치료 지식 개선을 주장할 수 없다. 원문·개별 답변·호출별 기록은 비공개 `results/codex-healthbench-question-reuse-probe-v1/`에 보존하고, 일반 집계는 [JSON](HEALTHBENCH_QUESTION_REUSE_PROBE.json)에 저장한다.
