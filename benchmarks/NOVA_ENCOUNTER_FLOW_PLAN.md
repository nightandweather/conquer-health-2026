# 내원 상황에 따른 대화 흐름 — 미실행 설계

2026-10-12 사용자 제안: 외래·응급 내원에서 무엇을 먼저 확인하는지, 환자 종류별로 대화를 나눌지 검토한다. **E04 제출 이후의 설계 기록이며 현재 제출 코드에 적용하지 않았다.** 새 모델 호출·추가 샘플·공식 평가 요청은 없다.

## 먼저 위험도, 그다음 방문 목적

장소와 긴급도를 따로 취급한다. 외래로 왔다고 안정하다고 단정하지 않고, 응급실로 왔다고 모두 같은 긴급 처치가 필요하다고 단정하지 않는다. 즉시 개입이 필요한지의 분류는 외래를 포함한 의료 접근 지점에도 적용된다. [WHO Interagency Integrated Triage Tool](https://www.who.int/tools/triage)

응급 상황에서는 기도·호흡·순환·의식 등 초기 평가와 필요한 안정화가 상세한 병력 청취보다 앞서거나 병행된다. 위급한 문제의 조기 인식과 처리가 우선이며 계속 재평가한다. 이 문서는 처치 프로토콜이나 자동 중증도 판정기를 구현한 것이 아니다. [WHO-ICRC Basic Emergency Care](https://www.who.int/publications/i/item/basic-emergency-care-approach-to-the-acutely-ill-and-injured)

안정한 환자와는 방문 이유·가장 걱정하는 점·오늘 해결하고 싶은 것을 먼저 맞춘다. 검사·치료 선택을 설명하고, 합의한 다음 단계와 재검토 시점을 확인한다. [NICE NG197 1.2.7–1.2.17](https://www.nice.org.uk/guidance/ng197/chapter/recommendations)

## NOVA용 제안: 고정 대본 대신 우선순위 분기

다음 표는 위 원칙에서 도출한 개발 설계다. 공식 NOVA 환자 유형이나 검증된 자동 분류가 아니며, 증례 정답을 미리 분류한 표도 아니다.

| 현재 확인된 상황 | 먼저 확인할 것 | 이어갈 흐름 |
|---|---|---|
| 위험 신호가 있거나 안정 여부를 모름 | 즉시 위험을 가르는 정보·필요한 진찰 | 위험도 확인을 우선; 필요한 긴급 평가·이송·의뢰 방향을 설명하고 허용된 기록에 남김 |
| 안정한 첫 방문·새 증상 | 주호소, 시작·변화, 환자 걱정 | 증상에 맞는 문진·진찰 → 잠정 판단과 불확실성 → 계획 설명 |
| 안정한 재진·만성질환 | 지난 진료 이후 변화, 치료 반응, 복약·부작용 | 새 위험 신호 확인 → 필요한 재평가 → 유지·변경 계획과 추적 |
| 검사 결과 상담 | 실제 제공된 결과와 환자가 궁금한 점 | 의미·불확실성 설명 → 추가 조치와 재검토 계획 |
| 약·치료 상담 | 실제 복약, 알레르기·부작용, 치료 목표 | 근거 있는 선택지와 이익·위험 설명 → 합의한 계획과 확인 사항 |

안정 여부가 불명확한 것을 자동으로 안정으로 채우지 않는다. 서로 겹치는 목적은 함께 보존하고, 대화 중 새 위험 신호나 목적 변경이 나타나면 분기를 갱신한다. 이미 제공된 정보는 다시 묻지 않고, 미응답·모호함·모순을 구분해 필요한 부분만 재확인한다. 증상별 질문은 고정된 한 질병 대본 대신 현재 가설을 구분하는 정보에 맞춘다.

안정적인 진료의 종료에서는 판단·치료 또는 처치 방향·필요한 검사·추적 조건·경고 증상·남은 질문을 다룬다. 치료가 필요하지 않거나 아직 결정할 수 없으면 그 판단과 이유를 남긴다. 계획을 실제 시행으로, 기록상의 교육 계획을 실제 환자 설명으로 바꾸지 않는다.

## 대회 실행 경계와 실험 조건

예선 에이전트가 받는 것은 시작 정보와 실제 문진·진찰 결과다. 제공되지 않은 외래/응급 장소, 활력징후 또는 과거 치료 사실을 만들어 분류하지 않는다. 예선 TEST는 사용할 수 없고 EXAM은 신체진찰 동작이며 처치 도구가 아니다. 실제 수행할 수 없는 검사·처치는 계획과 설명으로 구분한다. [NOVA 개발 가이드](https://nova.snubhai.org/docs/)

현재 E04는 최종 기록 지시만 변경했고 대화 분기는 변경하지 않았다. E04 결과 이후 별도 한 요인 후보를 설계할 때만 적용을 검토한다. 총턴·모델·검색·검토·예산을 함께 바꾸지 않고, 분기 오판·반복 질문·문진 누락·설명 누락·시간 증가를 합성 경로와 독립 감사에서 먼저 확인한다. 합성 검증은 임상 성능을 입증하지 않는다. 같은 공개 샘플 결과는 개발 비교로만 남기며 성능 향상을 미리 가정하지 않는다.
