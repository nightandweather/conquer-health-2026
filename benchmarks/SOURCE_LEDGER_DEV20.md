# 사용자 원문 출처 색인 개발 실험

이번 가설은 지침을 다시 쓰지 않고, 원문 사용자 발화를 재인용하는 결정적 출처 색인을 입력에 추가하면 정보 출처 혼동이 줄어드는지 확인하는 것입니다. 직전 개발 20문항 검토에서 정보 출처 오류가 남았습니다. v3/v4에도 이전 assistant의 제안과 사용자 정보를 구분하는 규칙이 이미 있으므로 같은 경고 문구를 강화하는 후보는 반복하지 않습니다. 이 관측만으로 이전 assistant 내용이 오류의 원인이라고 확정하지 않습니다.

## 비교 계획

원래 대화 배열을 P, 고정된 grounded-v2 지침 블록을 B, P에서 기계적으로 만든 출처 색인을 L(P)라고 합니다.

| 조건 | 저장된 대조군 | 계획한 후보 |
|---|---|---|
| 메시지 | `[system B, ...P]` | `[system B, user L(P), ...P]` |
| 원래 지침·대화 내용과 역할·순서 | 그대로 | 그대로 |
| 추론 / temperature / 출력 한도 | medium / 0 / 2,048 | 동일 |
| 모델·템플릿 | 기존 고정 digest와 템플릿 SHA | 실제 실행 전후 재확인 필요 |
| 호출 정책 | 기존 개발 20개 캐시 | 향후 최대 20개·문항당 1회 |

색인은 원래 턴 번호와 역할을 담고, 사용자 턴에만 원문 문자열을 그대로 넣습니다. assistant 턴에는 번호와 역할만 넣고 그 답변 내용을 색인에 복사하지 않습니다. 원래 assistant 내용은 P 안에 그대로 남습니다. 색인을 제거하면 대조군 요청 전체가 정확히 복원돼야 하며, 추가 메시지 이외의 요청 설정은 바뀌면 안 됩니다. 사용자 문자열의 공백·줄바꿈·Unicode·숫자·부정·인용도 보존합니다. 요약, 사실 추출, 새 환자 정보, 의학 판단, 정답·기준·검토 피드백을 넣지 않습니다.

**사용자 원문은 확인된 환자 사실을 뜻하지 않습니다.** 일반 질문, 가정, 제삼자 발언의 인용, 과거 assistant 답변의 재인용, 상충하거나 정정된 주장도 포함할 수 있습니다. 색인은 어디서 나온 문자열인지만 표시하며 내용의 진실성이나 임상적 의미를 인증하지 않습니다.

실험 요인은 출처 색인 메시지 추가라는 하나의 입력 표현 변경입니다. 원문 반복, JSON 구조, 메시지 경계·위치와 입력 토큰 길이가 함께 달라지므로 색인 의미만의 순수 효과나 역할 우선순위만의 효과를 분리하지 않습니다. assistant의 원문이 남아 있으므로 출처 오염 제거를 입증한 구조도 아닙니다.

## 대조군과 범위

대조군은 [직전 전달 위치 실험](INSTRUCTION_PLACEMENT_DEV20.md)의 `grounded_medium_system2048_v1` 캐시입니다. 개발 20행의 정상 18·빈 답변 실패 1·잘림 1과 원래 partial 상태를 모두 보존합니다. 실패나 잘림을 제외해 정상 답변만 골라 비교하지 않습니다. 별도의 좁은 검증 경로에서 원본 manifest·답변·summary·비교 파일의 고정 SHA, 실제 요청·선택 시도·행·모델·템플릿 출처를 확인해야 합니다. 기존 medium/2,048의 정상 17·실패 3 gate에 새 해시를 넣어 우회하지 않습니다. 기존 low 대조군 gate와 일반 CLI도 유지합니다.

개발 자료의 사용자 31턴·assistant 11턴을 사용하며 이력이 있는 문항은 5개입니다. 원래 평가용 180문항의 개별 입력·답변·검토 피드백은 사용하지 않습니다. 이번 실험이 새로운 독립 평가 모집단을 만드는 것은 아닙니다.

## 준비와 실제 생성의 구분

첫 준비 회차의 범위는 **호출 없는 준비 구현·검증**이었습니다. 그 회차의 새 답변 생성·모델 정보 조회·템플릿 조회는 모두 0회이며 품질 점수나 채택 판정은 없었습니다. 당시 실제 생성 실행기는 **NOT_READY**였고 그 immutable 준비 기록은 그대로 유지합니다. 캐시에 기록된 모델·템플릿 확인을 현재 런타임의 새 조회라고 표시하지 않습니다. 이전 기준 판정의 보류도 재판정하거나 수정하지 않습니다.

`healthbench_source_ledger_preflight.py`를 구현해 실제 저장된 개발 20행과 이전 비교 40행의 출처를 확인했습니다. 고정된 source·summary·비교·데이터·지침·기존 실행 코드 핀, 선택된 실제 시도와 빈 답변·잘림의 증거를 검증했습니다. 20개 모두 원문·지침 보존, 추가 색인 제거 시 대조군 요청 해시 복원, messages 외 설정 고정이 확인됐습니다. 출력에는 원문과 실제 색인을 넣지 않습니다. 새 합성 검사 16개, private 전체 347개와 공개 지정 10개 모듈의 224개 검사가 통과했습니다. 공개 전체 테스트는 아닙니다. 독립 코드 감사에서 발견한 다른 코드 경로 지정 우회 옵션은 제거했고 실제 checkout의 고정 코드만 확인하도록 검사했습니다.

준비 도구는 예상 해시를 교체하거나 실제 생성을 실행하는 옵션이 없습니다. 과거 캐시 파일이 달라지면 새 해시를 넣어 통과시키지 않고 중단합니다. 이번 준비 artifact는 별도 비공개 회차에 저장했으며 기존 답변과 판정은 그대로입니다. 준비 당시 답변 비교 화면은 직전 실제 전달 위치 실행의 결과를 표시했습니다.

이후 별도 `healthbench_source_ledger_cycle.py`에서 실제 payload와 attempt에 이 색인을 전달하는 경로와 실패·잘림 포함 20개 비교 패킷을 구현했습니다. 실행 전·중·후 출처·모델·템플릿·코드 핀과 패킷 변조를 확인하며 중단 시 실제 호출·미호출·이미 받은 답변·작성된 패킷 수를 보존합니다. 기존 producer 3개와 준비 도구는 변경하지 않았습니다. 유효한 UTF-8 답변은 provider envelope가 잘못된 경우에도 별도 원문 증거로 보존합니다. 원래 캐시의 잘린 답변도 비교와 중단 집계에 포함합니다.

실행기 합성 검사 25개·private 전체 372개·공개 지정 11개 모듈 249개와 독립 코드 감사가 통과했습니다. 실제 저장된 20개 요청에서 같은 설정·지침·원문과 정확한 역변환을 다시 확인한 뒤 한 후보의 첫 실제 실행을 시작했습니다. 생성 완료와 새 독립 내용 검토는 별도 단계이며 새 품질 판정이 나기 전에는 개선이나 채택을 주장하지 않습니다. 의학 지식·응급 행동·최종 기록의 안전성이 이 색인만으로 좋아진다고 예상하지 않습니다. 중복 입력의 시간·토큰 증가와 출력 잘림 위험도 별도로 기록합니다.

준비 출력에는 해시·일반 조건·집계만 저장하고 실제 색인 JSON과 질문·답변·기준·환자 정보·개별 검토 근거는 공개하지 않습니다. 새 전용 비공개 폴더와 한 작성자의 범위를 사용합니다. mkdir과 최초 inode 확인 사이 같은 UID의 빈 폴더 교체를 완전히 배제하지 못하는 기존 한계도 유지합니다.

보류 해소, 새 중대한 오류 없음, 비교 가능한 대조군 대비 전체 품질 개선이 채택 조건입니다. 실제 NOVA 여러 턴 진료와 제출 에이전트에는 별도 검증이 필요합니다. 공식 HealthBench/NOVA 점수나 임상 안전 인증이 아닙니다.

## 실제 생성 관측

| 관측 | 고정 system 대조군 | 사용자 원문 색인 후보 |
|---|---:|---:|
| 정상 / 빈 답변 실패 / 잘림 | 18 / 1 / 1 | 20 / 0 / 0 |
| 생성 호출 | 기존 20 | 신규 20 |
| 요청 시간 합 | 168.513초 | 175.137초 |
| 전체 실행 시간 | 168.918초 | 175.685초 |
| 입력 / completion / 총 토큰 | 7,613 / 17,338 / 24,951 | 9,637 / 16,406 / 26,043 |

2026-10-12 06:16:42–06:19:38 UTC의 별도 실행에서 20문항을 각각 한 번 호출했습니다. 후보는 모두 비어 있지 않은 stop 답변이며 차단·미호출·재호출·잘림은 0입니다. 기존 대조군의 빈 답변 1개와 비어 있지 않은 잘림 1개를 포함한 전체 20행·partial 상태·원문은 그대로 보존합니다. 새 모델 정보 조회 43회·템플릿 조회 43회는 생성 20회와 별도로 기록합니다. 20개 실제 요청·시도의 색인 해시·설정과 40행 출처 해시 및 20개 A/B 패킷을 교차 확인했습니다.

요청 시간 3.93%·총 토큰 4.38% 증가는 서로 다른 시점의 단일 실행 관측입니다. 입력 토큰은 늘고 completion 토큰은 줄었으며 completion을 내부 추론과 최종 답변으로 분리하지 않았습니다. 전체 20문항의 내용과 새 중대한 오류를 확인하기 전에는 실패나 잘림이 없어진 것만으로 품질 개선이나 채택을 주장하지 않습니다. 설정·시간·토큰을 가린 새 검증자 두 명이 전체 40기록 검토를 완료했습니다.

## 독립 내용 검토와 미채택

기준 판정은 78개 확정·6개 보류이며 기존 빈 답변 실패 1기록의 2개 기준은 판정에서 생략했습니다. 기준 점수 34기록·별도 생성 실패 0점 1기록·점수 보류 5기록으로 구분합니다. 읽기 화면의 숫자 35개에는 별도 실패 0점이 포함됩니다.

이번 새 검토의 가능한 기준 점수 범위는 대조군 **49.17–57.50**, 후보 **50.83–55.00**으로 겹칩니다. 전체 확정 점수·의료 정답률·신뢰구간이 아닙니다. 같은 원문 대조군도 이번 패킷에서 새로 판정했으므로 이전 회차 범위와 연결해 개선율을 계산하거나 보류 증감을 이전 보류의 해소로 표시하지 않습니다. 기존 원문·판정·기준·점수는 유지합니다.

새 중대한 약물 정체성 오류를 원문과 공식 허가사항으로 확인했고, 보류 6개와 전체 품질 개선 미확인으로 **미채택**입니다. 모든 후보 답변이 생성됐다는 관측은 의학적 정확성이나 안전성을 뜻하지 않습니다. 개별 질문·답변·기준·검토·확인 근거는 비공개로 보관합니다. 같은 출처 색인 후보를 재호출하거나 NOVA 에이전트에 적용하지 않으며 이 가설에서 실제 시험한 후보는 하나입니다.

공식 일반 채점 정의와 논문의 불확실성 분류를 확인했지만 특정 기준의 문구·배점 방향 모순을 바로잡을 공식 정정 근거는 얻지 못했습니다. 이전 보류는 바꾸지 않았고 같은 기준만 재판정하도록 반복 배정하지 않았습니다. 다른 보류도 출처 확인과 적용 문턱에 관한 미확인 상태로 유지합니다. 다음 호출은 새로운 개발 근거와 비교 가능한 다른 한 변수 계획이 검증된 경우에만 시작합니다.
