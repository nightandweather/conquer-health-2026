# 진료 시점 일관성 회귀 점검 — HBT02

2026-10-12. [저장한 설계](HEALTHBENCH_CARE_TIMING_DESIGN.md)에 따라 기존 개발 대화의 고정된 네 지점에서 답변을 한 번씩 생성했다. **3개는 완전한 답변, 1개는 출력 한도에 도달한 빈 답변이었다.** 네 답변이 모두 완전해야 한다는 사전 조건을 충족하지 못해 맹검 임상 비교를 진행하지 않았으며 후보는 미채택이다.

## 실제 실행

| 항목 | 결과 |
|---|---:|
| 신규 후보 / 원래 개발 입력 | 1개 / 4개 |
| 신규 생성 요청 / 재시도 / 추가 대화 진행 | 4 / 0 / 0 |
| 완전 응답 / 실패 | 3 / 1 |
| 빈 답변 / `length` 종료 | 1 / 1 — 같은 기록 |
| 내용이 있는 잘린 답변 | 0 |
| 미실행 입력 / 미확정 전송 | 0 / 0 |
| 생성 요청 시간 합 | 66.619초 |
| 보고 입력 / 보고 출력 / 기록된 합계 토큰 | 2,790 / 5,418 / 8,208 |
| 사용량 미보고 응답 | 0 |
| 모델 메타데이터 / 템플릿 조회 | 8 / 8 |
| 환자 생성·자동 채점 API / NOVA 샘플·공식 제출 | 모두 0 |


후속 [오프라인 진단](HEALTHBENCH_COMPLETION_DIAGNOSTICS.md)에서 합계 토큰의 직접 보고/계산 출처가 저장되지 않았음을 확인했다. 위 입력·출력 보고값과 합계 수치는 유지하며, 합계의 원래 출처는 미확인이다. 원래 집계 JSON은 당시 기록으로 보존한다.

빈 답변 실패와 한도 종료는 서로 다른 두 실패가 아니다. 해당 응답은 제공자가 출력 2,048토큰과 `finish_reason=length`를 보고했지만 최종 표시 내용은 비어 있었다. 출력 사용량에는 추론이 포함될 수 있다. 별도 표시 답변 토큰이나 내부 추론을 측정하지 않았으므로 정확한 원인을 단정하지 않는다.

시간은 생성 요청에 걸린 시간만 더한 값이다. 준비·모델 정보 확인·독립 감사와 전체 작업 경과는 포함하지 않는다. 기존 HBT01의 12회와 구분되는 새 요청 4회이며, 같은 후보나 대조군을 다시 호출하지 않았다.

## 변경 범위와 검증

원래 저장된 요청의 첫 system 메시지 끝에 진료 시점의 일관성을 요구하는 두 문장만 추가했다. 다른 발화·설정은 그대로 유지했다. 원래 입력 4개마다 한 지점만 선택했으며, 알려진 모순 지점 하나와 첫 답변 보존 점검 세 개다. 후보 입력에는 교체 대상 답변, 이후의 명시적 오류 지적과 수정 답변, 이전 검토를 포함하지 않았다.

로컬 gpt-oss:20b, medium, temperature 0, 출력 한도 2,048토큰, 요청별 timeout 90초를 유지했다. 각 요청 전후 소스·모델 digest·템플릿 핀이 모두 일치했다. RAG·NOVA SDK·30자 행동 제한은 없다. 과거 의사 답변을 이어받은 고정된 맥락에서 다음 답변만 생성했으므로 후보가 처음부터 진행한 여러 턴 상담은 아니다.

별도 실행기는 고정 실험 폴더의 소유 기록과 호출 전 영구 예약을 사용한다. 다른 출력 폴더 생성, 동시 실행, 전송 여부가 미확정인 중단 상황을 통한 재호출을 차단한다. 원래 HBT01 실행기·이력과 E05 코드·ZIP은 보존했다.

새 합성 검사 20개와 독립 코드 감사가 통과했다. 공개 사본에서도 기존 여러 턴 실행기 검사 21개와 새 검사 20개, 지정한 2개 모듈의 총 41개 검사가 통과했다. 전체 검사 모음을 다시 실행한 것은 아니다. 이 검사는 출처·호출·저장 계약에 관한 것이며 임상 정확성을 평가하지 않는다.

## 판정

요청 전에 A/B 순서와 검토 조건을 고정했다. 그러나 검토 자료 내보내기는 네 답변 모두 완전하고 호출 후 핀이 일치해야 가능하도록 정했다. 실제 내보내기 시도는 빈 답변 때문에 거부됐고, 맹검 자료 폴더는 생성되지 않았다. 조건을 낮추거나 출력 예산을 늘려 이 회차를 구제하지 않았다.

따라서 **원래 진료 시점 모순의 해결 여부와 임상 정확성 비교는 `null`**이다. 완전한 세 답변만 골라 개선으로 해석하지 않는다. 새 맹검 임상 검토는 수행하지 않았고, 기존 HBT01의 보류 판정 세 건도 바꾸지 않았다. 기술적 실행 결과와 검토 전제 실패에 대한 독립 감사도 통과했다.

이 가설의 실행은 이번 한 번이다. 같은 후보를 반복 호출하지 않으며, 같은 가설이 두 번 실패하면 중단한다는 규칙은 유지한다. 후보는 검증된 개선으로 미채택이고 공식 HealthBench·NOVA 점수는 없다. 이 빈 답변이 추가 지시의 인과 효과라는 주장도 하지 않는다.

사후 선택한 개발 입력, 역사적 저장 대조군, 사례당 한 번 생성이라는 한계가 있다. NOVA E04/E05의 실제 대화나 점수 원인을 설명하는 자료로 사용하지 않는다. 원래 입력·답변·호출별 기록은 비공개 `results/codex-healthbench-care-timing-probe-v1/`에, 일반 집계는 [JSON](HEALTHBENCH_CARE_TIMING_PROBE.json)에 보존한다.
