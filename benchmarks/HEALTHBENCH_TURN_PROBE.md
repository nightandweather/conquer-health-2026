# HealthBench 파생 여러 턴 상담 연습 — HBT01

2026-10-12. 사용자의 요청에 따라 기존 개발용 20문항에서 상담에 맞는 4개를 입력만 보고 선택했다. 원래 환자 발화 전체를 첫 턴에 유지하고, 추가 질문에 대한 의사 답변을 여러 턴으로 관찰한다. 실제 Doctor 응답 12회(사례별 4·1·4·3턴)를 생성해 모두 완전한 응답을 받았다. 독립 임상 검토 결과는 아래에 구분해 기록한다.

## 실제 실행 집계

| 항목 | 결과 |
|---|---:|
| 개발 입력 / 의사 응답 | 4개 / 12회 |
| 완전 응답 / 잘림 / 빈 답 / 실패 / 재시도 | 12 / 0 / 0 / 0 / 0 |
| 후속 환자 입력 | 8회: 합성 질문 7, 원문 인용 답변 1 |
| 생성 요청 시간 합 | 106.411초 |
| 제공자가 보고한 입력 / 출력 / 전체 토큰 | 13,121 / 9,737 / 22,858 |
| 토큰 미보고 응답 | 0 |
| 코드 합성 검사 | private 21개, public 지정 1모듈 21개 통과 |
| 새 NOVA 샘플 / 공식 평가 제출 | 0 / 0 |

생성 요청 시간 합은 전체 작업 경과가 아니다. 출력 토큰에는 추론이 포함될 수 있고 표시된 답변 토큰만 별도 측정하지 않았다. 이전 준비 v1은 모델 호출 0회로 보존했고, 출처 핀 보강을 감사한 뒤 v2 실행 한 번에서 생성했다. 실제 모델 호출은 합성 검사의 가짜 호출과 구분했다.

요청마다 출처·실행 파일과 모델 digest·템플릿을 전후 확인했다. 모델 메타데이터 조회 24회와 템플릿 조회 24회는 12회 답변 생성과 별도다. 추가 환자 생성·자동 채점 API 호출은 0회이며, Codex의 독립 검토 작업은 이 API 집계와 별도다. 독립 검토자에게 설정·시간·토큰·의도한 결론은 제공하지 않았다.

## 고정한 범위

- 개발용 4개 입력만 사용한다. 평가용 180개와 원래 정답·채점 기준은 생성 및 환자 제어에 사용하지 않는다.
- 로컬 gpt-oss:20b, medium, 출력 2,048토큰, temperature 0, 호출당 90초, 재시도 0회다. 출력 한도는 추론과 답변을 함께 포함한다.
- 환자 제어자는 원문에 있는 사실만 답한다. 미제공 정보는 미확인으로 남기며 추가 질문은 합성 발화로 기록한다. 새 검사 결과·경과·치료 효과를 만들지 않는다.
- 사례당 의사 응답 최대 5회다. 한 긴급 사례는 첫 응답 후 권고 내용과 관계없이 종료하므로 실제 설계 상한은 총16회이며 전체 안전 상한은20회다. 짧게 종료하거나 실패·잘림이 생기면 호출 수는 줄어든다.
- frozen grounded_v2 일반 지침에 여러 턴 상담의 작업 형식만 추가한다. 질환별 치료 알고리즘은 추가하지 않는다. NOVA의 30자 행동 제한·진찰 도구·RAG는 적용하지 않는다.

## 독립 검토 결과

계획에 해당하는 내용은 실제로 나왔다. 다만 명시적으로 추가 질문을 한 뒤에야 나온 항목도 있고, 제시한 내용의 정확성 문제도 있었다.

| 내용이 처음 나온 시점 | 첫 답변에서 자발적으로 | 추가 요청 뒤에 | 해당 없음 |
|---|---:|---:|---:|
| 치료·관리 선택 | 3개 | 1개 | 0개 |
| 진찰·검사의 이유 | 0개 | 3개 | 1개 |
| 진료·추적 시점 | 2개 | 2개 | 0개 |
| 경고 증상 | 3개 | 1개 | 0개 |

표는 4개 대화에서 **내용이 등장했는지**를 센 것이다. 적절성 점수가 아니며, 긴급 사례에 불필요한 검사를 요구하지 않았다. 긴급 사례 1개에서는 첫 응답부터 즉시 조치가 제시됐지만 세부 실행 안내에는 문제가 있었다.

독립 검토에서 이미 제공한 사실의 재질문은 2개 대화, 보고된 증상을 더 확정적으로 바꾼 표현은 1개 대화에서 확인했다. 진료 시점이 한 응답 안에서 모순된 대화 1개는 환자 제어자가 그 모순을 명시적으로 지적한 다음 응답에서 수정됐다. 원래 오류와 수정 답변을 모두 보존했으며, 이를 자발적 오류 방지로 세지 않았다.

의학적 검토에서는 치료 분류·근거 설명, 검사 해석·모니터링 누락, 제품별 용법·금기 조건 범위 등의 문제가 확인됐다. 지적한 우려 18건(중등도 10, 낮음 8), 긍정 관찰 7건, 판단 보류 3건, 근거가 지지하지 않은 명제 2건을 구분했다. 관찰을 나누는 단위에 따라 개수가 달라지므로 이 수치는 오류율·정확도·안전 점수가 아니다. 판단 보류는 `null`로 유지했다. 심각도는 답변 문구에 관한 판단이며 실제 환자 위해는 관찰하지 않았다.

따라서 이번 결과는 **제안을 생성할 수 있지만, 그 제안의 정확성과 일관성을 추가로 확인해야 한다**는 개발 관찰로 남긴다. 검증된 품질 개선으로 채택하지 않았다. 자동 환자 생성 없이 원문 사실에 근거해 후속 대화를 만들고, 실제 응답을 독립 검토하는 실행 경로를 확보했다.

실행 집계는 [`HEALTHBENCH_TURN_PROBE.json`](HEALTHBENCH_TURN_PROBE.json)에 함께 저장했다. 개별 판정의 원문 증거와 공식 지침·원 논문 링크는 비공개 검토 파일에 보존했다.

## 해석의 한계

이 자료는 원래 HealthBench ID가 없는 복원본을 바탕으로 한다. 원문 전체가 첫 턴에 제공되므로 정보의 순차적 획득, 실제 검사 수행, 질병 경과와 치료 효과를 검증하지 못한다. 4개 입력은 전체 질환이나 대화 유형을 대표하지 않는다. 합성 후속 질문이 계획 설명을 유도할 수 있다.

새 대화 형식은 원래 단답 평가와 다르다. 기존 단답 답변을 동등한 대조군으로 두거나 새 대화에 원래 rubric을 그대로 적용하지 않는다. 공식 HealthBench 점수, NOVA 점수 또는 검증된 임상 개선으로 표시하지 않는다. 이 실험은 NOVA E05의 고정 소스·ZIP이나 접수를 변경하지 않는다.

원래 입력·환자 사실 목록·대화·개별 검토는 비공개 `results/codex-healthbench-turn-probe-v1/`에 저장한다. 계획·출처 핀·호출 수·상태·집계와 한계만 공개한다.
