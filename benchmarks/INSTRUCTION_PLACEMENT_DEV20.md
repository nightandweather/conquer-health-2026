# 고정 지침의 전달 위치 개발 실험

새 가설은 같은 grounded-v2 지침을 마지막 사용자 메시지의 부록에서 별도 system 메시지로 옮기면 지침 준수가 달라지는지 확인하는 것입니다. 개발 20문항의 검토에서는 이미 적힌 출처·불확실성·요청 범위 규칙을 지키지 않은 답변이 있었습니다. 이는 전달 위치 실험의 동기이며 역할 우선순위가 오류의 원인이라는 증거는 아닙니다. 이전 v3/v4는 지침 문구를 고쳤지만 전달 위치는 마지막 사용자 메시지로 유지했습니다.

## 고정 비교 조건

| 조건 | 저장된 대조군 | 계획한 후보 |
|---|---|---|
| 원래 대화 P | 그대로 사용 | 모든 role·content를 그대로 사용 |
| 같은 지침 블록 B | 마지막 user content 뒤에 추가 | 첫 system 메시지의 content로 이동 |
| 지침 블록 바이트 | `\n\n[` + 원래 지침 + `]` | 동일 |
| 추론 / temperature / 한도 | medium / 0 / 2,048 | 동일 |
| 모델 digest / 호출 정책 | 기록한 동일 모델 / 문항당 1회 | 동일해야 함 |
| 범위 | 개발 첫 20개, 정상 17·빈 답변 실패 3 | 개발 첫 20개 전체 |

지침 파일의 SHA-256은 `6a827a355cd215837e6ecfd1904945d7d2cfbf096535eca11933d54afcc5a0e5`입니다. 후보에서 B를 다시 마지막 user에 붙이면 대조군 요청으로 복원돼야 합니다. 두 요청의 messages 외 필드는 같고 원래 대화 P의 문자열·역할·순서는 보존해야 합니다. 기존 system 메시지가 있는 입력은 이 좁은 실험에서 거부합니다.

실험 요인은 **지침 전달 위치**이며 역할·메시지 경계·앞뒤 위치가 함께 바뀝니다. 우선순위만의 효과를 분리한 실험은 아닙니다. 대조군은 원래 medium/2,048의 실패 포함 20행이며 partial 상태·원문·출처 핀을 보존합니다. 최근 medium/4,096의 정상 18·실패 2 결과는 새 가설의 개발 근거로만 사용합니다. 4,096 대조군과 2,048 후보를 한 변수 비교로 섞지 않습니다.

## 공식 문서와 런타임 확인 범위

공식 OpenAI 문서는 gpt-oss가 Harmony 형식의 역할을 사용하고 역할별 지침 계층을 구분한다고 설명합니다. API의 일반적인 system prompt와 Harmony의 developer 역할은 채팅 템플릿에서 대응할 수 있습니다. [OpenAI Harmony 설명](https://developers.openai.com/cookbook/articles/openai-harmony), [gpt-oss Transformers 실행 설명](https://developers.openai.com/cookbook/articles/gpt-oss/run-transformers).

기존 로컬 메타데이터에 기록된 템플릿 SHA에 대응하는 [Ollama gpt-oss:20b 템플릿](https://registry.ollama.com/library/gpt-oss:20b/blobs/fa6710a93d78)은 `.System`을 Harmony developer 메시지의 지침으로 렌더링합니다. 호출 없는 준비 단계에서는 새 모델 조회를 하지 않았습니다. 이후 실제 실행에서는 같은 모델 digest와 템플릿 원문 SHA를 매 호출 전후에 확인했고 일치했습니다. 모델 정보 조회 43회와 템플릿 조회 43회를 생성 20회와 별도로 기록합니다. 대조군 시점의 템플릿 메타데이터는 기존 기록이며 새 대조군 조회로 표시하지 않습니다. [Ollama OpenAI 호환 API](https://docs.ollama.com/api/openai-compatibility)는 로컬 gpt-oss 호출 경로의 기준입니다.

## 현재 단계

호출 없는 준비 도구 `healthbench_placement_preflight`를 구현했고 실제 저장 기록 20건에서 준비 검증을 완료했습니다. 지침 블록·원문 이력 보존·정확한 대조군 역변환과 messages 외 설정 고정을 확인했습니다. 그 준비 단계의 새 생성·모델 조회는 각각 0회였으며 원래 준비 결과를 덮어쓰지 않았습니다. 합성 준비 검사 51개와 준비 단계의 private 전체 회귀 305개가 통과했고 독립 코드 감사도 통과했습니다. 기존 gate의 41개 변조 시나리오를 새 준비 API에서 회귀 검사하고 전달 위치 특화 검사 10개를 추가했습니다. 기존 일반 생성기·큐·low/2,048 대조군 gate는 유지합니다. 준비에서는 원래 medium/2,048의 20행·실패 3건·전체 summary·비교 파일의 외부 SHA와 입력·요청·지침·모델 핀을 검증합니다. 출력에는 식별자와 해시·일반 조건만 기록하고 원문 질문·답변·기준은 넣지 않습니다.

준비 통과는 실제 생성 지원을 뜻하지 않습니다. 준비 당시에는 실제 실행 경로가 없어 NOT_READY였습니다. 이후 별도 실행 경로와 실패 포함 A/B 패킷 경로를 구현·검증했으며, 2026-10-12 05:10:06–05:12:55 UTC에 로컬 모델·템플릿 확인 후 20문항을 각각 한 번 실행했습니다. 준비 도구 자체는 계속 호출 0회이며 실제 실행 준비 상태는 별도 실행기의 기록으로 확인합니다. 실제 실행 전에는 기본 요청 바이트 보존, 실제 candidate payload/attempt의 역할 전달, 입력·설정·시도·실패·출처 변조 거부를 합성 검사하고 독립 코드 감사를 마친 뒤에만 최대 한 후보·20회·문항당 한 번 호출할 수 있습니다.

실행 시 기존 실패 3건을 포함한 20문항 전체를 비교하고, 설정·시간·토큰을 가린 새 검증자가 사실·안전·정보 출처·이력·누락·반복 행동을 검토합니다. 보류 판정은 임의로 확정하지 않습니다. 이전 4,096 후보의 미채택과 보류 기록도 유지합니다. 지침 전달 변경은 모델의 지식 부족을 해소하지 않으며, 실제 NOVA 여러 턴 개선이나 공식 점수를 입증하지 않습니다.

고유한 비공개 결과 폴더와 한 작성자의 소유 범위를 사용합니다. mkdir과 최초 inode 기록 사이 같은 UID의 빈 폴더 교체를 완전히 배제하지 못하는 기존 한계를 유지합니다. 실제 질문·답변·기준·환자 정보·키·개별 검토 근거는 로컬 비공개 결과에 남깁니다.

## 실제 생성 관측과 내용 검토

| 관측 | cached user 부록 | 새 API system 지침 |
|---|---:|---:|
| 정상 / 빈 답변 실패 / 잘림 | 17 / 3 / 0 | 18 / 1 / 1 |
| 생성 호출 | 기존 20 | 신규 20 |
| 요청 시간 합 | 183.814초 | 168.513초 |
| 전체 실행 시간 | 184.209초 | 168.918초 |
| 입력 / completion / 총 토큰 | 7,464 / 18,184 / 25,648 | 7,613 / 17,338 / 24,951 |

차단·미호출·재호출은 0입니다. API 보고값의 completion 토큰을 내부 추론과 최종 답변으로 분리하지 않았습니다. 원래 대조군 20행과 partial 상태·빈 답변 3개는 그대로 유지합니다. 두 요청의 messages 외 필드는 같고, 20개 모두 실제 payload/attempt의 medium·2,048토큰·system_prefix와 원문 이력·지침 블록·역변환 해시를 확인했습니다. 모델·템플릿의 호출 전후 해시와 40행 출처 해시도 일치합니다.

요청 시간 8.32%·총 토큰 2.72% 감소는 서로 다른 시점의 단일 실행 관측이며 품질 향상이나 일반적인 인과 효과를 뜻하지 않습니다. 설정·시간·토큰을 가린 새 검증자 두 명이 20패킷·40기록을 검토했습니다. 기준 판정 76개·보류 2개이며 실패 4기록(대조군 3·후보 1)의 8개 기준은 판정에서 생략했습니다. 기준 점수 34기록·별도 생성 실패 점수 0인 4기록·점수 보류 2기록을 구분합니다.

이번 새 판정의 가능한 기준 점수 범위는 대조군 **57.50–59.17**, 후보 **59.17–60.83**입니다. 경계가 맞닿아 있어 엄격한 우위를 확정할 수 없고 공식 점수·정답률·신뢰구간도 아닙니다. 대조군도 이번 패킷에서 새로 판정했으므로 직전 회차의 범위와 연결해 개선율을 계산하지 않습니다. 이번 보류 수를 이전 보류의 해소나 모델 개선으로 해석하지 않습니다. 이전 판정과 원문 기준·답변은 그대로입니다.

새 중대한 안전·환자 정보 오류가 확인됐고 빈 답변 1개·잘림 1개·보류 2개가 남아 **미채택**입니다. 의심된 임상 사실은 공식 지침·원논문과 대조했고 개별 질문·답변·판정·근거는 비공개로 보관합니다. 시간·토큰 감소로 채택하지 않았습니다. 같은 system/2,048 후보는 다시 호출하지 않으며 이 가설에서 시험한 후보는 하나입니다. 다음 호출은 새로운 개발 근거와 다른 한 변수 비교 계획이 검증된 경우에만 진행합니다. 최신 실행 경로는 private 전체 331개·공개의 지정된 9개 모듈 208개 검사와 독립 코드 감사를 통과했습니다. 공개 전체 테스트는 아닙니다.
