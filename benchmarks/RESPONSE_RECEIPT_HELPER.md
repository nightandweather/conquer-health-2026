# 응답 구조와 토큰 출처 기록 보조 함수

2026-10-12. [빈 응답 오프라인 진단](HEALTHBENCH_COMPLETION_DIAGNOSTICS.md)에서 원래 응답 구조와 토큰 합계의 출처가 부족한 점을 확인했다. 별도 순수 함수 `response_metadata(response, *, selected_choice_index=0)`를 만들어 이 정보를 일반 JSON 메타데이터로 반환한다. 기존 HBT 실행기와 NOVA 런타임에는 연결하지 않았다.

이 함수는 이미 파싱된 응답을 인자로 받는다. 모델·네트워크·파일 작업을 수행하지 않고 입력을 수정하지 않는다. 실제 답변·추론 본문·식별자·알 수 없는 키와 문자열을 결과에 복사하지 않는다. 보조 함수의 반환값 자체도 새 임상 판정이나 호출 성공 판정이 아니다.

## 보존하는 정보

| 대상 | 기록 범위 |
|---|---|
| choices | 컨테이너 유형, 개수, 선택한 위치와 해당 choice/message의 사용 가능 여부 |
| 최종 content | 키 존재, 유형, 문자 길이, 엄격한 UTF-8 바이트 길이와 SHA256 |
| reasoning / reasoning_content | 키 존재, 유형, 문자·UTF-8 길이만 기록; 본문과 해시 제외 |
| finish_reason | 허용한 stop/length만 값으로 기록; 그 밖의 값은 원문 없이 구조로 표시 |
| 토큰 사용량 | 허용한 숫자 필드의 보고·누락·잘못된 값 상태와 실제 적용값의 출처 |

선택한 위치에 응답이 없으면 다른 choice를 대신 고르지 않는다. 누락/null/빈 문자열/잘못된 UTF-8의 구조를 구분하고 공백도 제거하지 않은 길이·해시로 측정한다. 공백만인지에 대한 성공 판정은 하지 않는다. 단독 surrogate는 대체 문자로 바꾸어 해시하지 않는다. 이 정보는 파싱된 객체에 관한 것이며 원시 HTTP 바이트를 증명하지 않는다.

토큰은 bool을 제외한 0 이상 `2**63-1` 이하의 정확한 정수만 유효하게 취급한다. 선택 인덱스도 이 범위의 정수만 허용한다. 이 범위는 JSON 직렬화를 위한 관측 계약이며 실제 모델의 한도나 예산이 아니다. 허용 필드는 prompt_tokens, completion_tokens, total_tokens와 알려진 숫자 하위 필드 reasoning_tokens/cached_tokens다. 원래 total이 없거나 잘못됐고 입력·출력이 유효하면 합계를 계산할 수 있지만, 원래 값의 상태와 계산했다는 출처를 함께 유지한다. 합계는 최대 `2**64-2`까지 정확하게 계산된다. 보고된 합계와 입력·출력의 합이 다르면 원래 보고값을 보존하며 조용히 일치시키지 않는다. 알 수 없는 수를 0으로 만들지 않는다. 세부 추론 토큰 수가 없으면 문자열 길이로 추정하지 않는다.

## 검증과 적용 범위

새 지정 모듈의 합성 검사 **34개**가 private와 공개 사본에서 모두 통과했고 독립 코드 감사도 완료했다. 같은 검사를 다시 실행한 수를 새 검사 수에 더하지 않았다. 전체 테스트 모음의 재실행이나 실제 모델 검증은 아니다.

검사는 누락·null·빈 문자열·공백·다국어·단독 surrogate, 복수 choice와 선택 범위, 추론 본문·해시 비노출, 사용량 보고/누락/잘못된 값/계산 출처, 큰 정수 직렬화, 입력 불변과 원문 비복사, 파일·소켓 접근 차단을 포함한다.

독립 감사에서 발견한 무제한 정수의 JSON 직렬화 경계를 위 숫자 범위로 보완했다. 기존 지정 109파일의 해시는 유지된다. 이는 범위를 정한 보존 확인이며 전체 백업이 아니다. 실제 모델·HTTP·메타데이터·템플릿 호출, 임상 재검토와 NOVA 제출은 모두 0이다.

과거 HBT02/HBT03의 원시 응답을 복구하거나 빈 답변 원인을 해결한 것은 아니다. 두 후보의 임상 비교 null·미채택, 호출 예약과 재시도 금지, 네 완전 응답 검토 조건을 유지한다. 새 모델 실험이나 NOVA 제출은 없으며 임상 정확성 개선도 주장하지 않는다.

후속 런타임 연결은 별도의 변경 범위와 출처 핀, 오류·중단 시 저장 순서 검증이 필요하다. 이번 결과는 독립 보조 함수의 합성 검증까지다. 일반 구현·검사 집계는 [JSON](RESPONSE_RECEIPT_HELPER.json), 비공개 검증 영수증은 `results/codex-response-receipt-helper-v1/`에 저장한다.
